## ⚠️ A RECURSIVE `grep` IN THIS HARNESS IS BLIND TO `next-prompt.txt`

`grep` is a shell **function**, not GNU grep: it execs `claude -G --ignore-files …`. **`--ignore-files` honours `.gitignore`**, `.gitignore:2` lists `next-prompt.txt`, and the file is **TRACKED anyway**. Reproduced at ELEVEN separate tips.
```sh

```
⚠️ **NORMALIZE THE PATH FORM BEFORE COMPARING ARMS** (wrapped prints bare paths, GNU prints `./`-prefixed). ⚠️ **Print FILE NAMES, never a count.** ⚠️ **`git check-ignore` REASSURES YOU WRONGLY** — git exempts TRACKED files, and it also exits 0 for a *negated* pattern, so it cannot discriminate an un-ignore exception either; `git status` is the discriminating check. ⚠️ **`command grep` DOES NOT SURVIVE `xargs`** (`xargs` execs a binary; `command` is a shell keyword) — inside `xargs` use `git grep` or `/usr/bin/grep`. ⚠️ **`grep -c` ON ZERO MATCHES IS TOOL-SPECIFIC**: only `git grep -c` prints nothing; GNU and the wrapper print `0`.
