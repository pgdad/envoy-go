## The FOUR LOAD-BEARING seams the PLAN must honor (all pinned at the SPEC — do NOT re-derive, do NOT weaken)

- **THE EMIT SITE: ONE SHARED `*tapFilter` VALUE IN BOTH `HTTPFilter` FIELDS.** `FilterChain.Destroy()` (`chain.go:665`) is `destroyOnce`-guarded and its loop is `if f.Decoder != nil { f.Decoder.OnDestroy() } else if f.Encoder != nil { f.Encoder.OnDestroy() }` (`chain.go:668-672`). The branches are **mutually exclusive**. So (a) a both-sided filter's `OnDestroy` fires **EXACTLY ONCE** — no once-guard is needed for correctness; and (b) **an Encoder-only `OnDestroy` is UNREACHABLE whenever a Decoder is present.** A natural-looking two-value decomposition (`Decoder: &decodeSide{}, Encoder: &encodeSide{}`) would silently NEVER emit a trace. Tap MUST install ONE shared `*tapFilter` in both fields — the landed `compressor` precedent (`compressor/doc.go:43`, `compressor.go:304`) — and hang the emit off its single `OnDestroy`. **Pin this with a unit test.**
- **THE `:status` WIRE-LEAK TRAP.** `:status` is NOT in the encode header map (`connection.go:736` says so verbatim); take it from `EncoderFilterCallbacks.ResponseStatus()` (ADR-0196). **NEVER mutate the map handed to `EncodeHeaders`:** `connection.go:738` passes `merged` (built `:733`) to `RunEncodeHeaders`, then `ReconcileOrderedHeaders(resp.Headers, merged)` at `:741` — a synthetic `:status` added to `merged` would be emitted as a literal `:status` header ON THE WIRE. Build a COPY. The IMPL needs a test proving no synthetic pseudo-header reaches the wire. Likewise `:scheme` is NEVER injected into the filter-visible request map (only `:method`/`:authority`/`:path` are) — UNassert it cross-side.
- **THE TRACE IS AN END-OF-STREAM ARTIFACT AND THE REFERENCE NEVER EARLY-EMITS.** Even when an `or_match` request arm is already TRUE at decode, the reference still emits the WHOLE stream (request + response) at stream end (the `orshort` probe). The tri-state (match/no-match/undetermined) exists to RESOLVE the tree, NOT to decide when to emit. Emission is unconditional at stream end, gated only on the resolved match.
- **THE FIXTURE MUST DRIVE A BODYLESS `GET` → `204`.** The reference ALWAYS captures bodies and there is NO suppression knob, but a **zero-length body message OMITS the `body` field entirely**. Only a bodyless request + a 204 response yields structurally headers-only traces on BOTH sides — which is what turns `request.body`/`response.body` ABSENT into a positive, breakable cross-side assertion. Do not "simplify" the fixture to a 200-with-body.
