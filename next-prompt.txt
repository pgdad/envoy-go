The three PLAN-time design decisions:
- **D-PLAN-1** — the `*.unknown`-keyed-on-(api_key, api_version) routing needs a per-api-key `maxVersion` column ADDED to the Appendix-B table (Appendix B has NO maxVersion column — transcribe the Kafka 3.9.1 per-key version ceilings from the message JSON / upstream resolver); `api_version > maxVersion(key)` → unknown; minVersion treated as 0 (the deprecated-low-version → unknown sub-case a recorded coverage boundary; the `0053` unknown-version arm tests the HIGH side with `api_version = 0x7FFF`).
- **D-PLAN-2** — decode-exception posture is per-exception `*.failure` + decoder RESET (resync the direction's private buffer) + Continue — NOT mongo-style lifetime sniffing-off (matches upstream `broker/filter.cc` `decoder->reset()`); the correlation map is NOT cleared on a decode reset.
- **D-PLAN-3** — the request decoder reads + VALIDATES api_key/api_version/correlation_id/client_id/tagged-fields (a malformed `client_id` NULLABLE_STRING length → `request.failure`), registering correlation AFTER the (api_key, api_version, correlation_id) triple but BEFORE the client_id attempt (the upstream `expectResponse`-on-`onFailedParse` parity); the response decoder is count-and-frame-skip on `correlation_id` ONLY, making the AMEND-K5 ApiVersions(18) response special-case IMMATERIAL to the count path (implemented + table-tested for the request side + completeness).

D-P3 RESOLVED: `0054` carries the `stat_prefix`-required arm ONLY; the api_keys-range / nested-rule reject arms stay unit-test-only. D-P6 RESOLVED: the tables are hand-transcribed static data (no code-gen), guarded by byte-stable golden tests.

The envelope: HEADER-ONLY decode both directions; FULL per-API-key counter parity recovering the api_key on the response side via the `correlation_id → (api_key, api_version)` per-connection map (ADR-0223 mutex; request decode on the read goroutine, response decode on the write goroutine); the four active features PARSE-ACCEPTED-behavior-DEFERRED; ZERO framework-seam extension (pure consumer; ZERO-touch on the ADR-0226 async halt/resume seam — never-halting, byte-identical R1; the filter implements `WriteFilter` even where observation-only to get the 28.1b post-handoff read seam).
