## ⚠️ A RECURSIVE `grep` IN THIS HARNESS IS BLIND TO `next-prompt.txt`

`grep` is a shell **function**, not GNU grep: it execs `claude -G --ignore-files --hidden -I --exclude-dir=.git …` in ugrep-compatible mode. **`--ignore-files` honours `.gitignore`**, `.gitignore:2` lists `next-prompt.txt`, and the file is **TRACKED anyway**. Reproduced at seven separate tips:
```sh
grep -rl 'STANDING DIRECTIVE (human, 2026-07-12)' . | sed 's|^\./||' | sort         # wrapped: ABSENT
command grep -rl 'STANDING DIRECTIVE (human, 2026-07-12)' . | sed 's|^\./||' | sort # GNU: PRESENT
grep -c 'STANDING DIRECTIVE (human, 2026-07-12)' next-prompt.txt                    # direct access WORKS
```
⚠️ **NORMALIZE THE PATH FORM BEFORE COMPARING THE TWO ARMS.** The wrapped arm prints bare paths while GNU prints `./`-prefixed ones, so a naive `comm` reports **every file as "only in GNU"**. ⚠️ **Print the FILE NAMES, never a count.** ⚠️ **`git check-ignore` REASSURES YOU WRONGLY** — it reports `next-prompt.txt` as *"not ignored"* (exit 1) because **git exempts TRACKED files from `.gitignore`** while ugrep does not. **Reliable forms: `command grep -r`, `git grep`, an explicit file list, or a recursive grep handed the FILE path directly.**

⚠️ **AND `grep -c` ON ZERO MATCHES IS TOOL-SPECIFIC.** Only **`git grep -c`** prints nothing. **GNU `grep -c` prints `0`** (and `path:0` per file on a list or `-r`), as does the ugrep wrapper. **Both still exit 1**, so an exit-code gate is wrong for either.

⚠️ **AND `\t` IN GNU ERE IS A LITERAL `t` — BUT THE TRAP FIRES IN THE OPPOSITE DIRECTION FROM THE DOCUMENTED WARNING.** The harness `grep` **shell function** NORMALIZES `\t`, while `command grep -cE '^\t_ '` returns 0. ⇒ **the trap bites exactly where gates run** (CI, scripts, `git grep`) and is **invisible interactively**. **Use `-P` unconditionally.**
