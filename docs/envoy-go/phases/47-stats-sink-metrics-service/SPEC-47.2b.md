## 1. Purpose / Mission

Deliver the SECOND-and-FINAL of the two deferred `metrics_service` knobs the 47.1 core leg strict-rejected: `emit_tags_as_labels=true`. When a bootstrap `stats_sinks[]` metrics_service entry carries `emit_tags_as_labels: true`, envoy-go's periodic registry-snapshot flush emits, per metric family, the family's tag SEGMENTS as `MetricFamily.metric[].label[]` `LabelPair`s — the tag VALUE is STRIPPED from the family `name` (the dotted residual name kept, dots collapsed) and emitted as a label keyed by the Envoy dotted tag-name (`envoy.cluster_name`, `envoy.http_conn_manager_prefix`, `envoy.response_code_class`, ...) — instead of inlining the full dotted name with zero labels the 47.1 mapping emits (`mapping.go:28`/`:37`). The label extraction REUSES the `internal/stats/name.go` SN1–SN9 tag-extraction RULES (ADR-0061; `flattenToProm` at `name.go:39` — the SAME logic that identifies which dotted segment is a tag and the response-code-class `_Nxx → _xx` collapse at `name.go:346`–`:348`), but emits a DIFFERENT projection from the Prometheus exposition form: the metrics_service form keeps the INTERNAL dotted residual name (NOT `envoy_`-flattened) and the DOTTED `envoy.`-prefixed tag key (NOT the Prometheus underscore key) — D-MS-LABEL/-KEY (§11). Labels apply to BOTH Counter and Gauge families (the knob is name-model, not value-model — UNLIKE the 47.2a Counter-only deltas; D-MS-LABEL-GAUGE). Metric VALUES stay CUMULATIVE-ABSOLUTE (`emit_tags_as_labels` changes only the name/label split, not the value — D-MS-LABEL-VALUE), so when `report_counters_as_deltas` is absent/false the value model is value-identical to 47.1 (last-seen == cumulative). The transform is sink-owned (parameterized by the per-`StatsSinkConfig` `EmitTagsAsLabels` bool; two sinks may differ), parallel to the 47.2a per-sink `deltaState` (`sink.go:68`/`:110`–`:111`) — it builds the sink's OWN families, NEVER mutating the shared `Flusher` snapshot fan-out. This composes ENTIRELY on the landed 47.1+47.2a substrate (ADR-0262/ADR-0263): NO new package, NO new go.mod module, NO new BackendKind, +0 stat surface. Byte-identical to the 47.1 no-labels path when `emit_tags_as_labels` is absent/false (the full differential, including `0089`/`0090`, is the regression anchor). It ANCHORS ADR-0264; **its IMPL FLIPS ROW 47 `done`** (the FINAL sub-leg per ADR-0106 + `reference_roadmap_split_phase_row_done`); the Observability family STAYS OPEN.

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-29, contrib-v1.37.2 — an H1 downstream :10000 `stat_prefix=ingress_http` → a `hashicorp/http-echo` backend `dms-backend:5678`, K=7 requests fired ~350ms apart [spanning multiple flush windows], with a bootstrap `metrics_service` `stats_sinks[]` entry [V3 transport, **`emit_tags_as_labels: true`**, `grpc_service.envoy_grpc.cluster_name=c_metrics`] + `stats_flush_interval=0.5s`, exporting to a driver-owned h2c label-dumping `MetricsService` receiver reachable by `host.docker.internal:4319` on a shared bridge `dmsnet` per `reference_docker_probe_bridge_network`; **decode-ran proof: 90+ `StreamMetricsMessage`s received, 5852 label-bearing family lines captured; `MSG#1 identifier.node.id="probe-node-id" cluster="probe-cluster"`**) CONFIRMED the brainstorm's reuse hypothesis (the SN-rule extractors ARE the substrate) but DECISIVELY pinned the emitted name/label FORM — which the brainstorm left as the genuine live-probe unknown (D-MS-LABEL). The findings sharpen FIVE design pins:

- **AMEND-MSL-NAME-DOTTED-RESIDUAL (the family `name` is the INTERNAL dotted name with the tag-VALUE segment removed and dots collapsed — NOT the Prometheus `envoy_`-flattened base).** Live finding (D-MS-LABEL): `cluster.<name>.upstream_rq_total` → `name="cluster.upstream_rq_total"`; `http.<prefix>.downstream_rq_total` → `name="http.downstream_rq_total"`; the tag value is NEVER present in the family name (`grep -c 'name="cluster.backend'` == 0). The residual KEEPS DOTS (`cluster.upstream_rq_total`, NOT `envoy_cluster_upstream_rq_total`). **Consequence for envoy-go:** the metrics_service label form is NOT `flattenToProm`'s output string (which is `envoy_`-prefixed + dot→underscore). envoy-go must produce the DOTTED residual = the internal `Name()` with the tag-value segment(s) removed (the SN-rule extraction already identifies WHICH segment is the tag value; the residual is the dotted name minus that token). The shared-core-vs-parallel-extractor decision is D-MS-LABEL-REUSE (§12, a PLAN call).
- **AMEND-MSL-KEY-DOTTED-ENVOY (the `LabelPair.name` is the Envoy DOTTED tag-name `envoy.<tag>` — NOT the Prometheus underscore key `envoy_<tag>`).** Live finding (D-MS-LABEL-KEY): the distinct label keys captured across the whole stream were EXACTLY `envoy.cluster_name`, `envoy.http_conn_manager_prefix`, `envoy.listener_address`, `envoy.response_code_class`, `envoy.response_code` — every key DOTTED after the `envoy` prefix, the rest underscored. **Consequence:** envoy-go's `name.go` SN-rule keys are the PROMETHEUS underscore form (`envoy_cluster_name` at `name.go:50`, `envoy_http_conn_manager_prefix` at `:60`, `envoy_listener_address` at `:82`, `envoy_response_code_class` at `:348`). The metrics_service key is the SAME tag-name with only the leading `envoy_` → `envoy.` (the projection `"envoy." + strings.TrimPrefix(key, "envoy_")` — only the prefix changes, the rest of the key stays underscored). The reference's metrics_service path emits the PRE-Prometheus-flattening dotted tag name; envoy-go re-derives it from its SN-rule keys by that prefix swap (D-MS-LABEL-REUSE).
- **AMEND-MSL-MULTI-TAG (a single name can yield MULTIPLE labels — the prefix tag AND a response-code-class tag — with the name collapsing `_Nxx → _xx`).** Live finding (D-MS-LABEL-MULTI): `http.<prefix>.downstream_rq_2xx` → `name="http.downstream_rq_xx"` + labels `{envoy.http_conn_manager_prefix=<prefix>, envoy.response_code_class="2"}`; `cluster.<name>.upstream_rq_xx` → `name="cluster.upstream_rq_xx"` + `{envoy.cluster_name=<name>, envoy.response_code_class="2"}`; `listener.<addr>.http.<prefix>.downstream_rq_xx` → THREE labels `{envoy.listener_address, envoy.http_conn_manager_prefix, envoy.response_code_class}`. **Consequence:** envoy-go's SN4 status-class collapse (`name.go:346`: `statusClassRE` → `base = m[1] + "_xx"` + label `{envoy_response_code_class: m[2]}`) reproduces the `_2xx → _xx` + `response_code_class` split EXACTLY — the metrics_service label path layers the prefix-tag extraction (SN1/SN2/SN3) THEN the SN4 status-class collapse on the residual, both reusing `name.go`. So `http.hcm_local.downstream_rq_2xx` → `name="http.downstream_rq_xx"` + `{envoy.http_conn_manager_prefix=hcm_local, envoy.response_code_class="2"}` is a cross-side-reproducible TWO-label assertion (a richer `0091` subset member than the single-label splits).
- **AMEND-MSL-LABELS-ON-BOTH-TYPES (labels apply to BOTH Counter AND Gauge families — the knob is name-model, NOT value-model; CONTRAST the 47.2a Counter-only deltas).** Live finding (D-MS-LABEL-GAUGE): `cluster.<name>.membership_total` (GAUGE) and `cluster.<name>.membership_healthy` (GAUGE) carried `{envoy.cluster_name=<name>}` labels identically to the COUNTER families; `http.<prefix>.downstream_rq_active` (GAUGE) carried `{envoy.http_conn_manager_prefix=<prefix>}`. **Consequence:** the 47.2b label transform touches BOTH the `*stats.Counter` (`mapping.go:26`) AND the `*stats.Gauge` (`mapping.go:35`) arms (unlike 47.2a, which is Counter-only). The transform is a pure name/label rewrite applied to every family regardless of type.
- **AMEND-MSL-VALUE-CUMULATIVE (the metric VALUE stays cumulative-absolute under `emit_tags_as_labels` — the `0091` assertion is `Family(key).value == K` last-seen, NOT a delta-SUM barrier).** Live finding (D-MS-LABEL-VALUE): `cluster.upstream_rq_total{envoy.cluster_name=backend}` read `val=14` cumulative after 14 requests (last-seen == cumulative, NOT a per-flush delta); the knob is orthogonal to value semantics. **Consequence:** `0091` (with `emit_tags_as_labels:true` ALONE, `report_counters_as_deltas` absent) keeps 0089's CUMULATIVE `value == K` last-seen assertion model — NO post-convergence delta-SUM stability barrier is needed (that was a 47.2a/`0090` concern; `reference_delta_sink_differential_stability_barrier` does NOT apply to the labels-only fixture). The `0091` driver polls-to-converge until the keyed family's last-seen value == K.

Additional confirmed pins (no amendment): untagged stats keep their FULL dotted name with an EMPTY label set (D-MS-LABEL — `listener_manager.listener_create_success` → `name="listener_manager.listener_create_success"` labels=`[]`; the SN-rule prefix switch has no match → no extraction); labels live on the `Metric` (`metric[].label[]`), NOT the family (matches `MetricFamily.metric[].label[]` `LabelPair`); the metric `type` is UNCHANGED (`COUNTER`/`GAUGE` as 47.1); the reference BOOTS `emit_tags_as_labels:true` clean (D-MS-REJECT-2 — reference-parity-accept); +0 metrics_service self-stats (D-MS-STATS-FINAL-2 — `/stats` grep empty save the generic `server.dropped_stat_flushes:0`).

### 3.2 The sink-owned label transform (`internal/statssink`)

The 47.1 mapping carries the FULL dotted internal `Name()` (`mapping.go:28`/`:37`) with zero labels. 47.2b adds a label transform parameterized by the per-`StatsSinkConfig` `EmitTagsAsLabels` bool, PARALLEL to the 47.2a per-sink `deltaState`:

- **The transform (per family, both types — AMEND-MSL-LABELS-ON-BOTH-TYPES):** from the family's internal dotted `Name()`, extract the tag SEGMENTS via the `name.go` SN-rules → produce `(residualDottedName, []LabelPair)`; rewrite the family `Name` to the residual and set the `Metric.Label` to the `LabelPair`s. The residual NAME is the internal name with the tag-value token(s) removed (dots collapsed; AMEND-MSL-NAME-DOTTED-RESIDUAL); the label KEY is the Envoy dotted tag name (`"envoy." + strings.TrimPrefix(snKey, "envoy_")`; AMEND-MSL-KEY-DOTTED-ENVOY); a name matching NO SN-rule keeps its full name + empty labels. The response-code-class `_Nxx → _xx` collapse + label is layered via SN4 (AMEND-MSL-MULTI-TAG). The metric `type` and `value` are UNCHANGED (cumulative-absolute; AMEND-MSL-VALUE-CUMULATIVE — UNLESS `report_counters_as_deltas` is also set, in which case the delta transform has already rewritten the Counter VALUE; the two are orthogonal).
- **D-MS-LABEL-REUSE (a PLAN call):** the `name.go` `flattenToProm` (`:39`) produces the PROMETHEUS projection (`envoy_`-prefixed dot→underscore base + underscore label keys). The metrics_service form needs the PRE-flattening DOTTED projection (dotted residual + dotted `envoy.` keys). Two realizations: **(a)** refactor `name.go` to expose a shared extraction core returning a NEUTRAL `(residualDottedName, []tagPair{dottedKey,value})` consumed by BOTH `flattenToProm` (which then underscores + `envoy_`-prefixes) AND the statssink label mapping (which uses the dotted form directly); or **(b)** a PARALLEL extractor in `internal/statssink` keyed off the same prefix rules. (a) is DRY but touches the hot `flattenToProm` path (regression risk to the Prometheus admin endpoint — the full prom differential is the guard); (b) duplicates the SN-rule matching but isolates the change. The PLAN picks one (the live form is fixed; the projection arithmetic is mechanical — only `envoy_`→`envoy.` on the key + the dotted residual). The acyclic-import check holds either way (the transform stays inside `internal/statssink`, importing `internal/stats`).
- **Placement (D-MSL-PLACEMENT — a PLAN call):** the label transform is sink-owned, applied in the sink's `Submit` path PARALLEL to the 47.2a `deltaState.apply` (`sink.go:110`–`:111`): a `labels *labelMapper` field on `MetricsServiceSink` (non-nil ⇒ `emit_tags_as_labels`), `if s.labels != nil { batch = s.labels.apply(batch) }`. **HARD CONSTRAINT (the SPEC pins, the PLAN realizes):** the shared absolute `snapshot()` batch slice (`flusher.go:47`) is fanned to EVERY sink; the label transform MUST NOT mutate the shared `dto.MetricFamily`/`dto.Metric` in place (that would corrupt a sibling no-labels sink) — it builds the sink's OWN families (cloning the rewritten Name + new Label). **Compose order with deltas (both knobs true):** apply `delta` (rewrites Counter VALUE) THEN `labels` (rewrites Name + Label) — the two are orthogonal (disjoint fields), so the order is mechanically independent, but pin `delta`-then-`labels` for determinism; the label transform reads `family.Name` (untouched by the delta transform) so it composes cleanly on the delta batch.
