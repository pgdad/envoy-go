## 1. Purpose / Mission

Deliver envoy-go's FIRST stats-export sink and FIRST consumer of the bootstrap `stats_sinks[]` field: when the bootstrap carries a `metrics_service` `stats_sinks[]` entry, envoy-go dials the configured `grpc_service.envoy_grpc.cluster_name` cluster (via `grpcclient.Dialer`), opens the `MetricsService.StreamMetrics` client-streaming RPC, and every `stats_flush_interval` (default 5s) snapshots the frozen process-global `stats.Registry` (`Walk`) and streams the whole metric set as structured `io.prometheus.client.MetricFamily` protos — the first message carrying `identifier { node }`, each subsequent message carrying only `envoy_metrics`. The mapping is cumulative/no-labels: each `Counter` → a `COUNTER` `MetricFamily` with the absolute `Load()` value, each `Gauge` → a `GAUGE` with the absolute value, the FULL dotted internal name (tags inlined), ZERO `LabelPair`s, a flush-time `timestamp_ms` — the `report_counters_as_deltas=false` + `emit_tags_as_labels=false` defaults (deltas + tags-as-labels are 47.2). This is the project's FIRST **periodic registry-snapshot** sink (all prior Observability sinks — ALS, OTLP-log, tracing — are per-request/event-driven) and the FIRST genuinely-new bootstrap-level background subsystem in a long stretch (ONE new Go package `internal/statssink`). It composes on THREE already-built substrates — the phase-06.1 `stats.Registry.Walk` contract (ADR-0059), the phase-18 `grpcclient.Dialer` + the ALS client-streaming sink template (ADR-0158/ADR-0255), and the `cmd/envoy-go/main.go` post-Freeze background-goroutine + LIFO-drain wiring — adding ONE new package and **ONE new go.mod module** (`github.com/prometheus/client_model` — the FIRST new module in the Observability family). Byte-identical and stat-surface-identical when no metrics_service `stats_sinks[]` entry is configured (every non-sink path untouched; the full differential is the regression anchor). It ANCHORS ADR-0262; the row-47 Observability-family row flips `done` only at the FINAL leg (47.2) IMPL (ADR-0106 + `reference_roadmap_split_phase_row_done`); the Observability family STAYS OPEN.

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-29, contrib-v1.37.2 — an H1 downstream → an `hashicorp/http-echo` backend, K=7 requests, with a bootstrap `metrics_service` `stats_sinks[]` entry [V3 transport, `grpc_service.envoy_grpc.cluster_name=metrics_cluster`] + `stats_flush_interval=1s`, exporting to a driver-owned h2c `MetricsService` receiver reachable by the hostname `receiver`, all on a shared bridge per `reference_docker_probe_bridge_network`; **decode-ran proof: 13–20+ `StreamMetricsMessage`s received, each carrying 88→222 `MetricFamily` entries; `cluster.backend.upstream_rq_total.counter.value == 7 == K`; node `id=probe-node-id`/`cluster=probe-cluster` on msg #1**) CONFIRMED most brainstorm hypotheses but surfaced FOUR amendments that reshape the differential and the reject roster.

- **AMEND-MS-FIELDS-CONFIRMED (the default mapping is EXACTLY the brainstorm hypothesis: full dotted name, tags inlined, ZERO `LabelPair`s, cumulative absolute, `help` empty).** Live finding (D-MS-FIELDS): every `MetricFamily` carries the FULL DOTTED internal name with tag VALUES inlined into the name (e.g. `cluster.backend.upstream_rq_total`, `cluster.backend.external.upstream_rq_200`, `http.ingress_http.downstream_rq_2xx`), `type` ∈ {`COUNTER`,`GAUGE`,`HISTOGRAM`}, `metric[0].counter.value`/`gauge.value` = the CUMULATIVE ABSOLUTE value (`counter.value:7` == K; `gauge.value` the live gauge), `help` EMPTY on every family, and **0/207 families carry any `LabelPair`** under `emit_tags_as_labels` unset. This validates the §2.5 cumulative/no-labels mapping verbatim — the `/stats` internal-name model, already cross-side name-compatible (the Prometheus + redis StatsAsserter precedent).
- **AMEND-MS-HISTOGRAM-PRESENT (the reference EMITS `HISTOGRAM` families [e.g. `cluster.backend.upstream_rq_time`]; envoy-go has ZERO histograms [ADR-0060] ⇒ the metric-type map is closed to `COUNTER`/`GAUGE` and the cross-side differential subset MUST be a COUNTER/GAUGE name-subset, NOT a whole-family-set comparison).** Live finding (D-MS-FIELDS histogram sub-prong): the reference's `Walk`-equivalent registry includes histograms, exported as `type:HISTOGRAM` `MetricFamily`s. envoy-go's `stats.Registry` has ONLY `Counter`+`Gauge` (histograms deferred at phase 06.1, ADR-0060) — so envoy-go's mapping emits NO histogram family, the `MetricFamily.type` `SUMMARY`/`HISTOGRAM`/`UNTYPED` arms are unreachable, and `MetricsServiceConfig.histogram_emit_mode` is moot. **Consequence for the differential:** the TWO sides have DIFFERENT total family sets (different stat surfaces — envoy-go's registry ≠ the reference's, and the reference adds histograms envoy-go lacks), so the `0089` differential CANNOT assert family-set equality; it asserts the VALUE of a deterministic COUNTER/GAUGE NAME SUBSET that BOTH sides register identically (the already-proven cross-side-name-compatible subset). This REPLACES the brainstorm's implicit "the metric set" framing with an explicit name-subset assertion.
- **AMEND-MS-TIMESTAMP-ALWAYS-SET (every exported metric carries a flush-time `timestamp_ms`; envoy-go MUST populate it; the VALUE is non-deterministic ⇒ UNasserted cross-side).** Live finding (D-MS-FIELDS timestamp sub-prong): 207/207 families carried a non-zero `metric[].timestamp_ms` (the flush wall-clock in ms, e.g. `1782734137801`). The brainstorm left `timestamp_ms` "UNasserted regardless" — that stands, but the IMPL MUST set it (the reference always does; an unset `timestamp_ms` would be a visible divergence even though the value is not asserted). 47.1 stamps the flush time on every `metric`.
- **AMEND-MS-REFERENCE-STRICTER (UNLIKE the permissive tracing reference [46.1], the metrics_service reference HARD-REJECTS a missing/unknown gRPC cluster AND deprecated `transport_api_version:V2` at config-load ⇒ envoy-go's `HasCluster`/Dialer-cluster-exists boot-reject AND the non-V3 reject are REFERENCE-PARITY, not envoy-go-strict departures; the envoy-go-strict rejects are the KNOB VALUES + sibling sink types + `stats_flush_on_admin`).** Live finding (D-MS-FLUSH/D-MS-REJECT, 7 config variants): a `cluster_name: nonexistent` (V7) → the reference REJECTS at load (`Unknown gRPC client cluster 'nonexistent'`, exit 1); `transport_api_version: V2` (V3-variant) → REJECTS (`V2 xDS transport protocol version is deprecated`, exit 1). BUT `report_counters_as_deltas:true` (V1), `emit_tags_as_labels:true` (V2), `histogram_emit_mode:SUMMARY` (V4), a sibling `StatsdSink` typed_config (V5), and `stats_flush_on_admin:true` (V6) ALL BOOT (permissive). So envoy-go is REFERENCE-PARITY on the cluster-exists + non-V3 rejects (both sides reject), and envoy-go-STRICT (ADR-0080 anti-silent-divergence) on the knob values it does NOT yet honor (deltas/tags-as-labels at 47.1 — deferred to 47.2), the sibling sink TypeURLs (lifting one TypeURL from the ADR-0064 silent-ignore set requires explicit per-sibling rejects, `reference_strict_reject_sibling_typeurl_gap`), `histogram_emit_mode` (moot — no histograms), and `stats_flush_on_admin` (the flush-on-scrape oneof variant, deferred). This is the inverse of 46.1's AMEND-TRACE-NO-BOOT-REJECT: there the reference was permissive on a missing cluster; here it is strict.
- **AMEND-MS-NO-SELF-STATS (the reference registers ZERO `metrics_service`-sink self-stats; the only sink-related stat is the generic bootstrap-level `server.dropped_stat_flushes`; the surface delta N is an envoy-go exporter-counter NAMING DECISION, default 0, IMPL-pinned ≈0–2).** Live finding (D-MS-STATS): `curl /stats | grep -iE 'metrics_service|stat_sinks|stats.sink'` → no matches; no `metrics_service`/`stat_sink` family in the 207-name export; the generic `server.dropped_stat_flushes` exists (bootstrap-level, applies to all sinks, already-registered) but is NOT metrics_service-scoped. So the reference surface delta for the sink is **+0**. The 45.1/46.1 precedent added `*_written`/`*_sent` + `*_dropped` exporter counters as an envoy-go naming decision; whether 47.1 adds an analogous small `internal/statssink` counter set (e.g. flush-success/flush-drop) is a §7/§12 IMPL decision — NOTE the self-referential subtlety (any sink self-counter registered before Freeze ITSELF appears in the next flush's `MetricFamily` set, §2.7). The default to MATCH the reference is **+0**; an envoy-go exporter-counter addition is N≈1–2 (IMPL registration-test pinned).

Additional confirmed pins (no amendment): identifier-once on msg #1, re-armed on reconnect (D-MS-LIFECYCLE); one FULL-snapshot batch per flush (not which-changed deltas); the default `stats_flush_interval` is 5s (probed with the field omitted → 5.00s spacing); the reference auto-reconnects on receiver close (re-sends the identifier on the fresh stream); the `identifier{node}` carries `node.id`+`node.cluster` (envoy-go-settable, cross-side assertable) plus `user_agent_name`/`user_agent_build_version`/`extensions[]` (impl-specific — UNasserted).

### 3.2 The `MetricsServiceClient` typed wrapper (`internal/grpcclient/grpcclient.go` — the `ALSClient` precedent, ADR-0158, CLIENT-STREAMING)

`StreamMetrics` is a CLIENT-streaming RPC (`StreamMetrics(stream StreamMetricsMessage) returns (StreamMetricsResponse)` — the client `Send`s many, server `CloseAndRecv`s one), EXACTLY the shape of ALS `StreamAccessLogs` — so the wrapper mirrors `ALSClient` (`grpcclient.go:279`), NOT the unary `OTLPLogsClient`/`OTLPTracesClient`:

```go
type MetricsServiceClient struct {
    conn      *grpc.ClientConn
    stub      metricsv3.MetricsServiceClient
    target    string // cluster_name — for logs/errors
    closeOnce sync.Once
    closeErr  error
}
func NewMetricsServiceClient(d *Dialer, clusterName string) (*MetricsServiceClient, error) // d.DialContext → wrap
func (c *MetricsServiceClient) StreamMetrics(ctx context.Context) (metricsv3.MetricsService_StreamMetricsClient, error)
func (c *MetricsServiceClient) Close() error // sync.Once-guarded
```

- Typed-import `metricsv3 "github.com/envoyproxy/go-control-plane/envoy/service/metrics/v3"` (the client-streaming `StreamMetrics(ctx) (MetricsService_StreamMetricsClient, error)`; the returned stream has `Send(*StreamMetricsMessage) error` + `CloseAndRecv() (*StreamMetricsResponse, error)`; FullMethod `/envoy.service.metrics.v3.MetricsService/StreamMetrics`, verified §11). NO change to `Dialer`.

### 3.3 The `internal/statssink` package — the `Flusher` + the `MetricsServiceSink` + the `Counter`/`Gauge` → `MetricFamily` mapping

ONE new package. Its pieces (the PLAN decides file decomposition):

- **The `Flusher` (`flusher.go`) — the NEW bootstrap-level subsystem:** `type Flusher struct { reg *stats.Registry; interval time.Duration; sinks []Sink }` with `Start(ctx context.Context)` (a `time.NewTicker(interval)` loop) + `flushOnce()` (a `reg.Walk(fn)` snapshot building `[]*dto.MetricFamily`, handed to each `Sink.Submit(batch)`) + a final flush on `ctx.Done()` before stop (D-MS-FLUSH — the reference's drain behavior; the PLAN pins whether 47.1 emits a final flush). Started AFTER `bs.Stats.Freeze()` (`main.go:325`) so the `Walk` snapshot is lock-clean and race-free (ADR-0059). The `Flusher` is process-global (one snapshot of the one process-global `Registry` per tick).
- **The `Registry` → `[]MetricFamily` mapping (`mapping.go`):** per metric from `Walk` (the `Metric` interface — `Name()`/`Type()`; the concrete `*Counter.Load() uint64` / `*Gauge.Load() int64`):
  ```
  Counter c → &dto.MetricFamily{ Name: c.Name(), Type: COUNTER,
                 Metric: [{ Counter: { Value: float64(c.Load()) }, TimestampMs: nowMs }] }
  Gauge   g → &dto.MetricFamily{ Name: g.Name(), Type: GAUGE,
                 Metric: [{ Gauge:   { Value: float64(g.Load()) }, TimestampMs: nowMs }] }
  ```
  `emit_tags_as_labels=false` ⇒ the full dotted `Name()`, ZERO `LabelPair`s (AMEND-MS-FIELDS-CONFIRMED); `report_counters_as_deltas=false` ⇒ the absolute `Load()` (AMEND-MS-FIELDS-CONFIRMED); `TimestampMs` = the flush wall-clock in ms (AMEND-MS-TIMESTAMP-ALWAYS-SET). NO `Help`. NO histogram arm (AMEND-MS-HISTOGRAM-PRESENT — envoy-go has none). The `Name()` is registry-validated (`IsValidName`) at registration time, so no charset guard is needed in the mapping (the names are not config-derived — `reference_dynamic_stat_name_charset_guard` does not bite here).
- **The `MetricsServiceSink` (`sink.go`) — the ALS-grpcsink client-streaming lifecycle:** `type Sink interface { Submit(batch []*dto.MetricFamily); Close() error }`; the impl mirrors the ALS `GrpcAccessLogSink` (`internal/accesslog/grpcsink.go` — `newGrpcSinkWithCapacity`/`Submit`/`run`/`Close`): a bounded channel fed by the `Flusher` (one batch per flush tick), a writer goroutine (`run`) that lazily establishes the `StreamMetrics` stream on the first batch, sends the `identifier { node }` ONCE per stream life (re-armed across a reconnect — D-MS-LIFECYCLE), `Send`s each batch as ONE `StreamMetricsMessage{ EnvoyMetrics: batch }`, re-opens the stream once + re-sends the identifier + the WHOLE batch on a `Send` error, and drops + counts on a full channel; `Close` drains the in-flight stream (`CloseAndRecv`) + cancels the stream ctx, idempotent via `sync.Once`. The `node *corev3.Node` (the bootstrap node — reused from the ALS/OTLP sink precedent, `NewOTLPAccessLogSink` takes one) feeds the identifier. UNLIKE the per-event ALS sink (which batches `Record`s on a size/interval trigger), the metrics `Flusher` is the trigger — each flush is one already-complete batch, so the sink's internal buffer is a 1-deep handoff, not a size/interval accumulator (a simplification the PLAN pins, D-MS-SINK-BUFFER).

### 3.4 The exported `MetricFamily` shape (§11 D-MS-FIELDS, AMEND-MS-FIELDS-CONFIRMED)

Per the live probe: `MetricFamily{ name:<full dotted internal name>, type:COUNTER|GAUGE, help:"", metric:[{ counter|gauge:{value:<abs>}, timestamp_ms:<flush ms> }] }`, ZERO `LabelPair`s. The `StreamMetricsMessage.identifier.node` carries `id`+`cluster` (the bootstrap node — cross-side assertable); envoy-go MAY additionally set `user_agent_name` (impl-specific, UNasserted). The cross-side-assertable target is the deterministic COUNTER/GAUGE NAME SUBSET (§8 / D-MS-SUBJECT), NOT the whole family set (AMEND-MS-HISTOGRAM-PRESENT — the surfaces differ).
