**What this phase is.** Phase 39 is the **FIRST Upstream-robustness-family row** — the first NEW feature family opened since §9 (Network filters) closed at phase 33 (phases 34–38 were all Load-balancing-family rows). It lands `Cluster.health_checks` (`[]core.config.core.v3.HealthCheck`, proto field 8) — **active** upstream health checking (periodic outbound probes that mark hosts healthy/unhealthy) over an HTTP + TCP + gRPC checker roster — plus the project's first per-host **health-state dimension** and the health-aware LB pick that makes all six LB constructs route only to healthy hosts (with a panic-threshold fallback). It is the family **keystone**: the host health-state primitive it introduces (i) unblocks the open Load-balancing family's 3 health-gated candidates {locality-weighted LB, priority load balancing, panic thresholds}, and (ii) is the substrate the sibling rows {outlier detection, circuit breakers, retries + hedging, connection pooling} compose with. Until phase 39, `Endpoint` carried no health field and `internal/cluster` had no background runtime.

**The envelope (BRAINSTORM; a pre-authorized 39.1/39.2 by-codec split).**

- **39.1 — the keystone + the HTTP checker** (this leg): the per-cluster host-health registry (`map[string]*hostHealth` keyed by `Endpoint.Addr()`; atomic healthy + consecutive-result counters; `Endpoint` unchanged) + the active-HC runtime (per cluster × per `health_check` background goroutine; `interval`/`timeout`-driven; `unhealthy_threshold`/`healthy_threshold` transitions; the `Manager.StartHealthChecks(ctx)` boot start + the `Manager.Drain()` cancel/wait — the project's FIRST cluster-level background runtime) + the HTTP probe codec (`GET <path>` + `expected_statuses`, reusing the H1/H2 client) + the health-aware LB pick (Approach A across all six constructs — skip unhealthy + re-pick; ring_hash/maglev walk-to-next-healthy preserving key stability; the `healthy_panic_threshold` fallback) + the `0066-health-check-http` differential. The two ADRs (ADR-0242 + ADR-0243) land here. Anticipated **~500–800 prod LoC / ~14–20 tasks**.
- **39.2 — TCP + gRPC checkers** (deferred): `tcp_health_check` (connect / send-receive) + `grpc_health_check` (`grpc.health.v1.Health/Check` over the H2 path), reusing the 39.1 health-state + runtime + LB substrate UNCHANGED (the framework-zero-touch second consumer, the thrift-33 reuse precedent). Anticipated +1 BackendKind (a gRPC SERVING responder) + a candidate `FuzzGrpcHealthResponse`. Its own SPEC/PLAN/IMPL; may itself split (TCP vs gRPC) at its SPEC.

**Key BRAINSTORM decisions.** (Q0) the next subject opens a NEW family — **Upstream robustness** (chosen over xDS/gRPC/HTTP3 as the foundational reliability layer; it unblocks the 3 health-gated LB candidates). (Q0b) the first sub-project = **active health checks** (the keystone — establishes the health boundary the family exists to deliver; chosen over the cleaner-to-differential retries/circuit-breakers). (Q1) the checker roster = **HTTP + TCP + gRPC**, split by codec (39.1 HTTP keystone / 39.2 TCP+gRPC). (Q2) the health-aware LB = **Approach A: pick-time filter + panic fallback**, with the health view **build-time-injected** (host health is CLUSTER state, NOT a per-request `Pick` widening — the deliberate CONTRAST with the ADR-0235 hash-key / ADR-0239 subset-match ctx-carry pick-inputs; the `Pick` signature + exported `Cluster` surface stay BYTE-STABLE; behavior-neutral when all healthy → every existing fixture stays byte-identical).

**The differential proof (poll-to-convergence; a NEW determinism shape).** ONE fixture (39.1): `0066-health-check-http` — an HTTP listener routing to a cluster with `health_checks: [http_health_check]` over {a LIVE HTTP backend, a DEAD unbound endpoint}, on BOTH sides, with short `interval`/`timeout` + low `unhealthy_threshold`. The driver POLLS the admin `/stats` until the dead host converges to unhealthy on BOTH sides (no fixed `time.Sleep`), THEN runs the load phase and asserts 100% of N requests land on the LIVE host + cross-side `health_check.*`/`membership_*` parity + `upstream_rq_total` cross-equal. The dead-host-via-unbound-address design needs **NO new BackendKind** (the live host reuses the HTTP backends; tail stays 33) and **NO new fuzzer** (the probe response reuses the fuzzed H1/H2 parser; a threshold-transition property test is unit-level; fuzzers stay 42). Every leg proven live via `-count=1` deliberate-breaks (drop-the-filter → traffic leaks to the dead host; break-the-poll-predicate → never converges).
