The architectural centerpiece is the Path B-async one-blast throttle algorithm (ADR-0137): on the endStream invocation of `DecodeData` / `EncodeData`, the filter computes `throttle = ceil(body / chunk_size) × fill_interval` where `chunk_size = limit_kbps × 1024 × fill_interval_seconds` (KiB/s units per §1.1 amendment 6; NOT kilobits-per-second as BRAINSTORM hypothesized), arms a `time.AfterFunc(throttle)`, and returns `DataStopIterationAndBuffer`. The AfterFunc callback fires `ContinueDecoding()` / `ContinueEncoding()`, releasing the accumulated body downstream/upstream in a single blast. On the non-endStream invocation the filter returns `DataContinue` (envoy-go HCM synchronous-dispatch deadlock avoidance per Task-14 finding (d); mirrors phase-13 buffer's analogous discipline at ADR-0128 §Decision); only the endStream invocation arms the timer; wire outcomes byte-equivalent. This diverges from reference Envoy's Path A rate-paced chunks at exact `fill_interval` cadence (forward-pointer to a future encode-side streaming framework phase per ADR-0137 §Consequences); decode/encode-side body bytes are byte-equivalent (bandwidth_limit does not transform bytes), which fixture 0017's byte-exact body assertion enforces.

The differential fixture `0017-http-bandwidth-limit` is the phase-closing non-vacuous evidence against reference Envoy v1.37.2: 6 scenarios across a two-listener topology — `/r-only` (response-only throttle), `/q-only` (request-only throttle), `/r-and-q` (REQUEST_AND_RESPONSE symmetric), `/tiny` (within-burst no-throttle), `/disabled` (per-route DISABLED-via-`enable_mode`), `/per-route-stat-prefix` (per-route override with own stat_prefix exercising INDEPENDENT-stats per ADR-0139). ## 7. Phase-done lessons learned

**Symmetric BOTH-direction filter as a structural data point.** Phase 15 ships the FIRST §9 row to use the ENCODER+DECODER `HTTPFilter` value with SAME `*filter` instance for a symmetric algorithm — same throttle math + same kbps-per-tick discipline + same Path B-async wire-shape on both sides + same timer-arming logic. **ZERO framework deltas — phase-13/14 primitives reused without further additions.** Phase 15 is the FIRST §9 row since phase-12 csrf to ship ZERO framework deltas. It composes against phase-09 fault async-resume (`time.AfterFunc` + `ContinueDecoding/Encoding`) + phase-13 ADR-0128 decode-side body-buffering (the synthetic empty-terminal `RunDecodeData` + post-body CL reconciliation is the canonical primitive for "buffer the entire body until endStream") + phase-14 ADR-0131 encode-side `OverwriteBody` (anticipated, NOT invoked — the framework's buffered-return path on the encode-side returns bytes unchanged in the bandwidth_limit case because the filter does not transform bytes). **Lesson:** the framework-primitive accumulation through phases 09-14 has reached a maturity threshold where substantial new §9 rows can be implemented without further framework deltas.
