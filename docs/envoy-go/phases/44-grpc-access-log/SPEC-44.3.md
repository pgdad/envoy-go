## 1. Purpose / Mission

Make envoy-go's gRPC ALS sink honor the two `HttpGrpcAccessLogConfig` header-capture fields. At 44.1/44.2 the `GrpcAccessLogSink` maps the 10 plumbed `Record` operators into the structured `HTTPAccessLogEntry` (the `buildHTTPAccessLogEntry` 10-field mapping, `mapping.go`); `additional_request_headers_to_log` (field 2) and `additional_response_headers_to_log` (field 3) parse-accept-but-do-nothing (ADR-0255 / D-ALS-CONFIG-DEFER, carried by ADR-0256). Phase 44.3 makes the two fields LIVE: at parse time each configured header NAME is lifted into `ALSConfig` (lowercased); at request-finalization the HCM emit hooks (`emitAccessLog` H1 / `emitAccessLogH2` H2) capture the configured header VALUES from the request — AND from the response (a NEW emit-hook parameter; the response headers are not currently threaded to the emit site) — into two new `Record` maps (`RequestHeaders` / `ResponseHeaders`, lowercase-keyed); and `buildHTTPAccessLogEntry` maps each sink's configured header subset into the entry's `request.request_headers` / `response.response_headers` `map<string,string>` fields. The capture is gated on a non-empty configured set, so when NO ALS sink configures any additional headers (every existing fixture, including `0081`/`0082`) the `Record` maps stay nil and the hot path + emitted proto are byte-identical — the full differential is the regression anchor. The identifier-once stream lifecycle, the buffer machinery (ADR-0256), the lazy-establish, the reconnect-on-error, the bounded `closeDrainGrace` Close, and the two `access_logs.grpc_access_log.{logs_written,logs_dropped}` counters all carry UNCHANGED. It ANCHORS ADR-0257; the 44.3 IMPL six-gate flips **row 44 → `done`** (the FINAL chartered leg; ADR-0106 per-leg, no parent rollup) ⇒ but the **Observability FAMILY STAYS OPEN** (OTLP / tracing / stats sinks / tap remain future rows).

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-25, contrib-v1.37.2 — an H1 downstream → a real HTTP backend that emits distinctive backend-origin response headers, with an HCM `access_log[]` `HttpGrpcAccessLogConfig` carrying `additional_request_headers_to_log` + `additional_response_headers_to_log`, streaming to a containerized h2c gRPC ALS receiver that logs the per-entry `request.request_headers` + `response.response_headers` maps, on a shared bridge `alshdrprobe-net` per `reference_docker_probe_bridge_network`; requests fired with/without the configured headers, with a present-but-empty header, and with a multi-value header) drove these amendments:

- **AMEND-HDR-1 (map shape + key-case — captured into `request.request_headers` / `response.response_headers` `map<string,string>`; the KEY is the LOWERCASED header name, the VALUE is verbatim).** Live finding (D-ALS-HEADERS): a configured request header lands in `HTTPRequestProperties.request_headers` (proto field; `map<string,string>` — accessor `GetRequestHeaders()`); a configured response header lands in `HTTPResponseProperties.response_headers` (accessor `GetResponseHeaders()`). The map KEY is the header name LOWERCASED — config `X-Req-Mixed` → key `x-req-mixed`, config `X-Resp-Mixed` → key `x-resp-mixed` (HTTP header-name normalization). The map VALUE is the header value verbatim (case-preserved — `ReqMixedVal` / `RespMixedVal` stored unchanged).
- **AMEND-HDR-2 (missing ⇒ OMITTED; present-but-empty ⇒ empty-string ENTRY).** Live finding: a configured-but-ABSENT header is OMITTED from the map entirely (NOT an empty-string entry) — a request carrying only `x-req-foo` of four configured request-header names produced `request_headers` with `len=1` (only `x-req-foo`; the other three names absent). A configured header PRESENT with an empty value yields a key-PRESENT entry with value `""` (the `x-req-foo;` empty-value probe → `{"x-req-foo":""}`). So the discriminator is HEADER PRESENCE, not value emptiness: present (even empty) ⇒ key present; absent ⇒ key omitted.
- **AMEND-HDR-3 (multi-value ⇒ COMMA-joined, NO space, in WIRE ORDER).** Live finding: a header sent with multiple values is joined with a single `,` (comma, no space) preserving wire order — `x-req-multi: qv1` + `x-req-multi: qv2` → `{"x-req-multi":"qv1,qv2"}`; reversed-order `ZZZ` then `AAA` → `"ZZZ,AAA"` (NOT sorted — arrival order). Response `x-resp-multi: rv1` + `rv2` → `"rv1,rv2"`.
- **AMEND-HDR-4 (response source = the FINAL DOWNSTREAM (Envoy-mutated) response ⇒ the differential captures BACKEND-ORIGIN pass-through headers ONLY — the header-capture analog of AMEND-ALS-2's query-less faithful constraint).** Live finding: `additional_response_headers_to_log` captures the FINAL downstream response headers, INCLUDING Envoy-synthesized ones — `server: envoy` (added by Envoy, NOT set by the backend) was captured. Envoy-synthesized headers (`server`, `date`, `x-envoy-upstream-service-time`, …) DIFFER side-to-side (envoy-go does not synthesize the same set), so they are NOT cross-side assertable. The `0083` differential therefore captures only BACKEND-ORIGIN response headers that BOTH proxies pass through verbatim (e.g. `content-type`, set explicitly by the `HTTPFixedBody` 0006 backend to `text/plain`); it AVOIDS `server`/`date`/`x-envoy-*`. envoy-go captures from the response-header collection available at the emit site (`resp.Headers` — the post-action downstream-written response); whether envoy-go synthesizes a `server`/`date` header is an IMPL detail the differential sidesteps by asserting backend-origin headers only. A documented FAITHFUL fixture-drive constraint, NOT a behavior bug.
- **AMEND-HDR-5 (NO new stat — surface UNCHANGED at 1189).** Live finding (D-ALS-HEADERS stat sweep): the reference exposes NO header-capture-specific access-log stat — the only sink stats remain `access_logs.grpc_access_log.{logs_written,logs_dropped}` (`logs_written: 3` for 3 requests; the `http1.dropped_headers_with_underscores` / `http1.requests_rejected_with_underscores_in_headers` matches are generic HTTP/1 codec stats, NOT ALS-sink surface). Stat surface stays **1189** (non-H2 **1185**). `logs_written` continues to count ENTRIES (batch-invariant — carries from AMEND-BUF-4).

### 3.1 Config parse — lift the two header-name lists into `ALSConfig` (lowercased) (`internal/bootstrap/bootstrap.go`)

At 44.1/44.2 `parseGrpcAccessLog` (`bootstrap.go:361`) consumes `cluster_name` + `log_name` + the two buffer fields (the `additional_*_headers` fields parse-accept-but-inert). 44.3 lifts the two header-name lists:

- Extend `ALSConfig` (`bootstrap.go:190`) with two fields:
  ```go
  type ALSConfig struct {
      ClusterName              string
      LogName                  string
      BufferSizeBytes          uint32
      BufferFlushInterval      time.Duration
      AdditionalRequestHeaders  []string // additional_request_headers_to_log (field 2), lowercased at parse — AMEND-HDR-1
      AdditionalResponseHeaders []string // additional_response_headers_to_log (field 3), lowercased at parse — AMEND-HDR-1
  }
  ```
- In `parseGrpcAccessLog`, after the buffer reads, copy the two `[]string` lists with each NAME lowercased (AMEND-HDR-1 — the map key is the lowercased name, so normalize once at parse): `cfg.GetAdditionalRequestHeadersToLog()` / `cfg.GetAdditionalResponseHeadersToLog()` (accessors on `HttpGrpcAccessLogConfig`, NOT on `common_config` — these two fields live on the OUTER `HttpGrpcAccessLogConfig`, fields 2/3, NOT on `CommonGrpcAccessLogConfig`). Empty/absent ⇒ a nil/empty slice (the no-capture path). De-dup is NOT required (a duplicate name is harmless — a map write is idempotent), but lowercasing IS (the lookup + the map key are lowercase).
- The two fields are now CONSUMED (no longer in the inert set); `additional_*_trailers_to_log` + `AccessLog.filter` STAY parse-accept-but-inert.
- STRICT-REJECT roster UNCHANGED (no new reject — header capture is advisory; an unknown/garbage header name simply never matches a present header ⇒ omitted, AMEND-HDR-2).

### 3.2 The `Record` extension — two captured-header maps (`internal/accesslog/accesslog.go`)

The `Record` (`accesslog.go:29`) carries the 10 plumbed operators. 44.3 adds two maps:
```go
type Record struct {
    // ... the 10 existing fields ...
    RequestHeaders  map[string]string // captured additional_request_headers_to_log (lowercase key, comma-joined value); nil when no capture configured
    ResponseHeaders map[string]string // captured additional_response_headers_to_log (lowercase key, comma-joined value); nil when no capture configured
}
```
- Populated ONLY by the emit hooks (§3.3) when the HCM filter has a non-empty capture set; otherwise left nil (the byte-stable common path). The file sink (`Default` formatter) IGNORES these maps (its 10-operator format is unchanged — ADR-0067); only the gRPC sink reads them.
- The captured VALUES are snapshotted synchronously at emit time (before `Submit`): the writer goroutine drains the channel asynchronously and may flush long after the request finished, when the `*http.Request`/response are gone — so the capture MUST happen at the emit site, not in the sink. This is the load-bearing reason the `Record` (not the sink) carries the captured values.

### 3.3 Emit-hook capture + the response-header threading (`internal/filter/hcm`)

The capture happens at the two HCM emit hooks (`accesslog_emit.go` — `emitAccessLog` H1 `:18` / `emitAccessLogH2` H2 `:43`), which already build a `Record` and `Submit` it to every sink.

- **The capture set on the Filter.** The HCM `Filter` gains the union of configured capture names across all ALS sinks on that listener — `alsReqHeaderNames []string` + `alsRespHeaderNames []string` (lowercase, the dedup'd union; threaded from `bootstrap.ALSConfigs` into the HCM filter construction alongside the existing `accessLog []accesslog.Sink` plumbing, `config.go:110`/`:191`/`:285`). When BOTH are empty (every existing fixture), the emit hooks capture NOTHING and the `Record` maps stay nil — zero hot-path allocation, byte-stable.
- **Request-header capture (H1 + H2).** When `len(f.alsReqHeaderNames) > 0`, build `rec.RequestHeaders` by looking up each union name (case-insensitive) in the request headers and, if PRESENT, storing `lowercase(name) → comma-joined-values` (AMEND-HDR-1/2/3). H1 reads `r.Header` (`http.Header`, `map[string][]string` — `strings.Join(vals, ",")`); H2 reads the `H2Request.Headers` field slice (multiple same-name fields joined in slice order — the `h2UserAgent` case-insensitive-match idiom, `accesslog_emit.go:67`, generalized). Absent ⇒ key omitted; present-empty ⇒ `""`.
- **Response-header capture + threading.** `emitAccessLog` / `emitAccessLogH2` gain a response-header parameter (the final downstream response header collection — AMEND-HDR-4). This is a SIGNATURE change threaded through the ~12 call sites (`connection.go` H1 sites `:322`/`:442`/`:536`/`:637`/`:715`; `h2dispatch.go` H2 sites `:304`/`:386`/`:470`/`:516`/`:522`/`:550`): the upstream/action-response sites pass the response headers in scope (`resp.Headers` — the project `OrderedHeaders` collection of the post-action downstream-written headers, confirmed in scope at `connection.go:704` / `h2dispatch.go:304`); the error / local-reply sites that have NO upstream response (404/500 before any response) pass `nil` (only Envoy-synthesized headers would exist there, which the differential does not assert anyway). When `len(f.alsRespHeaderNames) > 0` and the param is non-nil, build `rec.ResponseHeaders` the same way. The exact parameter TYPE per codec (the H1 `resp.Headers` `OrderedHeaders` collection vs the H2 response-header representation) + the per-site source/nil-disposition is a PLAN/IMPL pin (D-HDR-RESPONSE-THREADING).
- **A shared capture helper.** A small `captureHeaders(names []string, lookup func(name string) ([]string, bool)) map[string]string` (lowercase-key, comma-join, omit-absent, empty-string-for-present-empty) factored once and called from both H1 + H2 for both request + response — the single source of the AMEND-HDR-1/2/3 semantics, exhaustively unit-tested.

### 3.4 The sink mapping — `buildHTTPAccessLogEntry` populates the two proto maps from the `Record`, filtered to the sink's configured lists (`internal/accesslog/mapping.go` + `grpcsink.go`)

The sink holds its OWN configured header lists (the per-sink faithful semantics — each Envoy access logger has its own `additional_*_headers_to_log`):
- `GrpcAccessLogSink` gains `additionalRequestHeaders []string` + `additionalResponseHeaders []string` (lowercase), plumbed through `NewGrpcAccessLogSink` (a signature extension — `main.go` passes `cfg.AdditionalRequestHeaders` / `cfg.AdditionalResponseHeaders`).
- `buildHTTPAccessLogEntry` is extended (signature: `buildHTTPAccessLogEntry(rec, reqHdrNames, respHdrNames []string)`, OR a post-mapping step on the built entry — a PLAN pin, D-HDR-SINK-FILTER) to populate `e.Request.RequestHeaders` / `e.Response.ResponseHeaders` by looking up each of the SINK's configured names in `rec.RequestHeaders` / `rec.ResponseHeaders` (the emit hook captured the UNION; the sink filters to its own subset). Absent from the `Record` map ⇒ omitted from the proto map (a name configured on the sink but not present on the request never entered the `Record` map ⇒ correctly omitted). When the sink's list is empty, leave the proto maps nil (the 44.1/44.2 behavior — byte-identical).
- For the common single-ALS-sink case the sink's list == the captured union, so the filter is a pass-through; the per-sink filter exists for the multiple-ALS-sink-with-divergent-lists case (unit-tested, §2 non-purpose for the differential).

### 3.5 Byte-stability

Byte-identical when no ALS sink configures any additional headers (the capture union is empty ⇒ the emit hooks capture nothing ⇒ `Record.RequestHeaders`/`ResponseHeaders` stay nil ⇒ `buildHTTPAccessLogEntry` adds no `request_headers`/`response_headers` ⇒ the emitted proto is identical; the response-header param is threaded but ignored). The file-only path + every non-access-log path + the `0081`/`0082` ALS fixtures (no header config) are untouched. The full differential (84-dir today → 85-dir with `0083`) is the regression anchor. NO new stat ⇒ the 1189 surface is unchanged for every existing fixture.

## 8. Differential fixture taxonomy (+1: `0083` cross-side EXACT captured-header maps)

### 8.1 `0083-grpc-access-log-headers` (cross-side EXACT on the captured request/response header maps, aggregated across entries)
An **H1** downstream listener → a route to the `HTTPFixedBody` (kind 4 = the 0006 backend, which sets `Content-Type: text/plain` + a fixed body), with an HCM `access_log[]` `HttpGrpcAccessLogConfig` whose `additional_request_headers_to_log` + `additional_response_headers_to_log` name a deterministic capture set, streaming to the driver-owned `accessloggrpc` receiver, on BOTH subject (in-process envoy-go) and reference (`contrib-v1.37.2`). Drive N requests carrying distinctive request headers + a configured-but-absent name + (optionally) a multi-value header, against the fixed-body backend; poll-to-converge until N entries arrive (a release barrier, NEVER a `time.Sleep` — `reference_concurrency_differential_release_barrier`).

- **Capture set (D-HDR-DIFFERENTIAL-DRIVE, §12):**
  - `additional_request_headers_to_log`: a present single-value name (e.g. `x-req-foo`), a configured-but-ABSENT name (e.g. `x-req-missing` — proves the OMIT behavior cross-side, AMEND-HDR-2), and (if cross-side-robust at IMPL) a multi-value name (e.g. `x-req-multi` — proves the comma-join, AMEND-HDR-3). The request-header capture is FULLY driver-controlled (the driver sets the request headers) ⇒ cross-side EXACT by construction.
  - `additional_response_headers_to_log`: `content-type` ONLY (the 0006 backend's backend-origin `text/plain` — AMEND-HDR-4: BACKEND-ORIGIN headers only; AVOID `server`/`date`/`x-envoy-*`). Both proxies pass `content-type` through verbatim ⇒ cross-side EXACT.
- **Cross-side assertion (EXACT, aggregated over all received entries — AMEND-ALS-3 carries):** for each of the N entries, `request.request_headers` matches both sides (e.g. `{"x-req-foo":"<val>"[, "x-req-multi":"<v1,v2>"]}` — the absent name OMITTED on BOTH sides) and `response.response_headers` matches both sides (`{"content-type":"text/plain"}`). Plus the 44.1 7-field structured subset carries (`request.{request_method,path[query-less],authority,user_agent}` + `response.{response_code,response_body_bytes}` + `protocol_version`==`HTTP11`) and `logs_written == N` on the subject. NO cross-side message/stream/batch-count assertion (AMEND-ALS-3: reference per-worker fragmentation).
- **The assertion that BITES against a no-capture regression:** a deliberate-break that disables the capture (the emit hook stops populating the `Record` maps, OR `buildHTTPAccessLogEntry` stops mapping them) makes `request.request_headers` / `response.response_headers` EMPTY ⇒ the EXACT map assertion FAILS (proving the capture LIVE; `reference_differential_break_protocol_count1` — `-count=1`).
- **UNasserted:** `common_properties.*`, the subject-absent reference fields, the `identifier.node` content, Envoy-synthesized response headers (`server`/`date`/`x-envoy-*` — AMEND-HDR-4), AND all stream/message/batch FRAMING on the REFERENCE side.
- **Reachability:** the driver-owned in-process `accessloggrpc` receiver reachable from BOTH the subject (`127.0.0.1`) AND the reference (`host.docker.internal` via the shared-bridge `ExtraHosts`, `harness.go:121`), the `0081`/`0082` precedent (D-ALS-RECEIVER-WIRING carries).
