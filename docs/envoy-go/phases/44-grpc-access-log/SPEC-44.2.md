## 1. Purpose / Mission

Make envoy-go's gRPC ALS sink honor the two `CommonGrpcAccessLogConfig` flush-policy fields. At 44.1 the `GrpcAccessLogSink` writer goroutine builds ONE `StreamAccessLogsMessage` per `Record` (a fixed simple flush — one `HTTPAccessLogEntry` per message); `buffer_size_bytes` (field 4) and `buffer_flush_interval` (field 3) parse-accept-but-do-nothing (ADR-0255 / D-ALS-CONFIG-DEFER). Phase 44.2 introduces a BUFFER inside the writer goroutine: each built entry is accumulated (tracking the running sum of serialized entry bytes); the buffer flushes a BATCH — all accumulated entries in one `StreamAccessLogsMessage.http_logs.log_entry[]` — when EITHER (a) the accumulated byte sum reaches `buffer_size_bytes` (the SIZE trigger) OR (b) a `buffer_flush_interval` timer elapses (the TIMER trigger), whichever fires first. This is NEW sink machinery: the 44.1 writer goroutine drained the channel one record at a time with no timer; 44.2 adds a `select` over the record channel AND a flush-interval ticker, plus a flush-the-pending-buffer-on-Close step. The identifier-once stream lifecycle, the lazy-establish, the reconnect-on-error, the bounded `closeDrainGrace` Close, and the two `access_logs.grpc_access_log.{logs_written,logs_dropped}` counters all carry UNCHANGED from 44.1. Byte-identical when no ALS `access_log` entry is configured (the file-only path is untouched; the full differential is the regression anchor). It ANCHORS ADR-0256; row 44 STAYS `in-progress` (44.3 header-capture remains); the Observability family STAYS OPEN.

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-25, contrib-v1.37.2 — an H1 downstream → a real HTTP backend, with an HCM `access_log[]` `HttpGrpcAccessLogConfig` streaming to an h2c gRPC ALS receiver, on a shared bridge `alsprobe-net` per `reference_docker_probe_bridge_network`; the receiver logs PER-MESSAGE batch sizes + identifier presence + arrival time; clean runs pinned `--concurrency 1` to collapse the reference's per-worker buffers into one) drove these amendments:

- **AMEND-BUF-1 (the flush semantics — EITHER-OR; byte accounting = the accumulated sum of per-entry serialized bytes).** Live finding (D-ALS-BUFFER): a worker's buffer flushes the accumulated batch on whichever fires first — the accumulated byte sum reaching `buffer_size_bytes` (SIZE) OR the `buffer_flush_interval` elapsing (TIMER). The byte accounting is the SUM of each buffered entry's serialized `HTTPAccessLogEntry` size (`proto.Size(entry)` == the C++ `ByteSizeLong()`); the flush fires when that running sum reaches the cap, and the CROSSING entry is INCLUDED in the flushed batch. Probe evidence: `buffer_size_bytes: 1500` with entries ≈356 B → clean 5-entry batches (4×356=1424 < 1500, 5×356=1780 ≥ 1500), four batches of 5 on ONE reused stream (identifier on the first message, ABSENT on the rest); the default cap → a 47-entry batch (46×≈349 < 16384, 47×≈349 ≥ 16384).
- **AMEND-BUF-2 (the defaults — `buffer_size_bytes` 16384, `buffer_flush_interval` 1s; explicit-0 = flush-every-entry).** Live finding: the default cap is **16384 bytes** (confirmed by the 47-entry size-only batch) and the default interval is **1s** (confirmed by the ~1s flush cadence: a 2-entry flush at 3257 ms then an 18-entry flush at 4252 ms, Δ≈995 ms). When the `UInt32Value` wrapper is ABSENT, apply 16384; when the `Duration` is ABSENT/zero, apply 1s. An EXPLICIT `buffer_size_bytes: 0` (wrapper present, value 0) degenerates to flush-every-entry (the size threshold `sum ≥ 0` is always satisfied) — matching the `buffer_size_bytes: 1` probe (per-entry immediate flush). envoy-go honors the wrapper's presence: absent ⇒ default 16384; present ⇒ the value (0 ⇒ flush every entry).
- **AMEND-BUF-3 (the reference buffers PER-WORKER-THREAD — framing fragments further ⇒ AMEND-ALS-3 REINFORCED; the differential asserts AGGREGATED payload cross-side, batching is a SUBJECT-side proof only).** Live finding: each Envoy worker thread owns its OWN gRPC ALS buffer + stream. Eight sequential requests under default concurrency landed on up to eight workers ⇒ eight separate streams, ONE entry each (no batching); pinning `--concurrency 1` collapsed them into one buffer/stream with clean batches. envoy-go's sink is PROCESS-GLOBAL (one bounded channel, one writer goroutine, one buffer) — a LEGITIMATE alternative framing that produces the SAME aggregated per-entry payloads. The reference's per-worker fragmentation is governed by its worker count (NOT pinned in the differential harness), so the `0082` differential CANNOT assert cross-side batch/message counts; it asserts the **per-entry payload aggregated across ALL received entries** (exactly the 44.1 AMEND-ALS-3 discipline, now REINFORCED), and proves buffering is LIVE with a **SUBJECT-side-only** batch assertion (envoy-go produced ≥1 message carrying ≥2 entries — which BITES against a regression to the 44.1 one-entry-per-message fixed flush).
- **AMEND-BUF-4 (NO new stat — surface UNCHANGED at 1189; the two existing counters carry).** Live finding (D-ALS-BUFFER stat sweep): the reference exposes NO buffering/flush-specific access-log stat — the only sink stats remain `access_logs.grpc_access_log.{logs_written,logs_dropped}` (the `*_bytes_buffered` / `http2.tx_flush_timeout` / `filesystem.*` matches in `/stats` are generic codec/cluster/file-sink stats, NOT ALS-sink surface, and are not part of envoy-go's surface). Stat surface stays **1189** (non-H2 **1185**). `logs_written` continues to count ENTRIES (++ once per entry in each flushed batch — NOT once per message); `logs_dropped` stays channel-full-overflow-only (AMEND-ALS-1).
- **AMEND-BUF-5 (drain — flush the pending buffer on Close BEFORE CloseAndRecv).** Live finding: on a graceful stop the reference's streams terminate `Canceled` with no special final-flush message — buffered-but-unflushed entries can be LOST on the reference (a per-worker drain). envoy-go's `Close()` already drains the channel deterministically (`closeDrainGrace`); 44.2 EXTENDS it to flush any pending buffered entries (one final `StreamAccessLogsMessage`) BEFORE `CloseAndRecv` — a recorded FAITHFUL improvement (no entry already handed to the sink is silently dropped at shutdown), consistent with the 44.1 bounded-shutdown discipline.

### 3.1 Config parse — lift the two buffer fields into `ALSConfig` with the reference defaults (`internal/bootstrap/bootstrap.go`)

At 44.1 `parseGrpcAccessLog` (`bootstrap.go:349`) consumes only `cluster_name` + `log_name` (the `buffer_*` fields parse-accept-but-inert). 44.2 lifts the two buffer fields:

- Extend `ALSConfig` (`bootstrap.go:183`) with two fields:
  ```go
  type ALSConfig struct {
      ClusterName         string        // common_config.grpc_service.envoy_grpc.cluster_name
      LogName             string        // common_config.log_name (empty is valid)
      BufferSizeBytes     uint32        // common_config.buffer_size_bytes (default 16384 when wrapper absent) — AMEND-BUF-2
      BufferFlushInterval time.Duration // common_config.buffer_flush_interval (default 1s when absent/zero) — AMEND-BUF-2
  }
  ```
- In `parseGrpcAccessLog`, after the STRICT-REJECT arms, read the two fields with the reference defaults (AMEND-BUF-2):
  - `buffer_size_bytes`: nil-safe via the GETTER — `if w := common.GetBufferSizeBytes(); w != nil { use w.GetValue() } else { default 16384 }`. `GetBufferSizeBytes()` returns the `*wrapperspb.UInt32Value` WRAPPER POINTER (nil when absent), NOT the uint32; `.GetValue()` yields the uint32 (an explicit 0 ⇒ flush-every-entry). Use the getter, NOT the direct field `common.BufferSizeBytes` (a nil-`common` direct-field read would panic — although in this control flow `common` is non-nil by the time the buffer reads run, since a nil `common` ⇒ nil `envoy_grpc` ⇒ the empty-cluster reject fires first).
  - `buffer_flush_interval`: `common.GetBufferFlushInterval().AsDuration()`; if nil/zero, default **1s**. This default is a HARD PANIC-GUARD invariant (not merely a fidelity default): `time.NewTicker(d)` PANICS for `d <= 0`, so the parse layer MUST coerce nil/zero → 1s before the value reaches the sink's `NewTicker` (§3.2). Any POSITIVE explicit value (including sub-second, e.g. the `0.2s` differential drive) is honored verbatim — only nil/zero coerces. The asymmetry with `buffer_size_bytes: 0` (honored as flush-every-entry) is deliberate: a 0-byte cap is a valid degenerate flush policy, a 0 interval is a `NewTicker` panic.
- The two fields are now CONSUMED (no longer in the §load-bearing inert set); `additional_*_headers` + `AccessLog.filter` STAY parse-accept-but-inert (44.3).
- STRICT-REJECT roster UNCHANGED (no new reject — the buffer fields are advisory tuning, not a reject surface).

### 3.2 The buffer machinery in `GrpcAccessLogSink.run()` (`internal/accesslog/grpcsink.go` — replaces the 44.1 fixed flush)

The 44.1 writer goroutine (`run()`, `grpcsink.go:127`) loops `for r := range s.ch` and Sends one message per record. 44.2 replaces the loop body with a buffered `select`:

- **New sink fields** (set from `ALSConfig` at construction): `bufferSizeBytes int` (the accumulated-byte cap), `bufferFlushInterval time.Duration` (the timer period). Plumbed through `NewGrpcAccessLogSink` (a signature extension — the main wiring at `main.go` passes `cfg.BufferSizeBytes` + `cfg.BufferFlushInterval`).
- **The writer goroutine** holds two pieces of per-flush state: `buf []*dataaccesslogv3.HTTPAccessLogEntry` (the pending entries) + `bufBytes int` (the running serialized-byte sum). It `select`s over BOTH the record channel AND a `time.NewTicker(s.bufferFlushInterval)`:
  ```
  ticker := time.NewTicker(s.bufferFlushInterval); defer ticker.Stop()
  for {
      select {
      case r, ok := <-s.ch:
          if !ok { flush(); break the loop -> CloseAndRecv }   // channel closed by Close (AMEND-BUF-5)
          rec, ok := r.(*Record); if !ok { log+continue }
          entry := buildHTTPAccessLogEntry(rec)
          buf = append(buf, entry); bufBytes += proto.Size(entry)
          if bufBytes >= s.bufferSizeBytes { flush() }          // SIZE trigger (AMEND-BUF-1)
      case <-ticker.C:
          flush()                                               // TIMER trigger (no-op if buf empty)
      }
  }
  ```
- **`flush()`** (a closure over the goroutine's `stream`/`sentIdentifier`/`buf`/`bufBytes`): if `len(buf)==0`, return (the timer no-op). Otherwise build ONE `StreamAccessLogsMessage{ http_logs: { log_entry: buf } }`, attach the identifier-once (the first successful flush of the stream's life — the 44.1 `sentIdentifier` discipline, re-armed across a reconnect), `stream.Send(msg)` with the SAME up-to-two-attempts reconnect-and-resend as 44.1 (on a `Send` error nil the stream + re-arm the identifier + resend the WHOLE batch once; a second failure drops the batch, logged-not-counted), then on success `logsWritten` += `len(buf)` (++ per entry — AMEND-BUF-4) and reset `buf = buf[:0]`, `bufBytes = 0`.
- **Single-goroutine discipline (the `-race` gate):** the buffer (`buf`/`bufBytes`) is touched ONLY by the writer goroutine; the ticker's internal goroutine only writes `ticker.C` (read by the writer). NO new shared mutable state ⇒ no new race surface beyond the 44.1 writer goroutine. The FULL-package `-race` gate (`reference_full_suite_race_after_background_mutator`) re-runs at IMPL regardless (the writer goroutine is the background mutator; the ticker is new machinery inside it).

### 3.3 The flush message — identifier-once, batched (carries 44.1 lifecycle)

A flushed `StreamAccessLogsMessage` carries `http_logs.log_entry[]` with ALL buffered entries (1..N). The FIRST successful flush of the stream's life attaches `identifier { node, log_name }` (re-armed across a reconnect); subsequent flushes carry only the `http_logs` arm (AMEND-BUF-1 probe: first batch `ident=PRESENT`, rest `ABSENT`). Lazy establish (the stream opens on the first FLUSH, not the first record) + reconnect-on-error carry from 44.1 (§3.5 of SPEC-44.1).

### 3.4 Drain semantics — flush the pending buffer on Close (AMEND-BUF-5)

`Close()` (`grpcsink.go:108`) is UNCHANGED in shape (close the channel; await `done` up to `closeDrainGrace`; `cancel()`; `client.Close()`). The CHANGE is in the writer goroutine's channel-closed path: when `range`/`<-s.ch` observes the closed channel, the goroutine FLUSHES the pending buffer (one final batched `StreamAccessLogsMessage`) BEFORE `CloseAndRecv` — so no entry already handed to the sink is silently dropped at shutdown (a faithful improvement over the reference's lossy per-worker `Canceled` drain). The `closeDrainGrace` + ctx-cancel still bound a wedged final flush.

## 8. Differential fixture taxonomy (+1: `0082` cross-side aggregated payload + subject-side batching proof)

### 8.1 `0082-grpc-access-log-buffering` (cross-side aggregated per-entry payload + a SUBJECT-side batching proof)
An **H1** downstream listener → a route to a fixed-body backend, with an HCM `access_log[]` `HttpGrpcAccessLogConfig` whose `common_config` sets `buffer_size_bytes` + `buffer_flush_interval`, streaming to the driver-owned `accessloggrpc` receiver, on BOTH subject (in-process envoy-go) and reference (`contrib-v1.37.2`). Drive N requests with a fixed `User-Agent` + `Host` + a **query-less** path (AMEND-ALS-2 carries) against a fixed-size backend body; poll-to-converge until N entries arrive (a release barrier, NEVER a `time.Sleep` — `reference_concurrency_differential_release_barrier`).

- **Buffer settings:** a LARGE `buffer_size_bytes` (e.g. `1048576` — never hit by N small entries) + a `buffer_flush_interval` so the TIMER trigger flushes envoy-go's single process-global buffer as a BATCH (the size-cap-based exact-batch-count is byte-accounting-fragile cross-side AND depends on the exact entry encoding — AVOIDED; the timer path is the robust deterministic lever). The exact values are a PLAN/IMPL pin (D-BUF-DIFFERENTIAL-DRIVE). **Coalescence-determinism caveat (the proof must not flake):** envoy-go's buffer is process-global with a SINGLE timer, so `maxBatchSize >= 2` only holds if ≥2 of the N entries land in one flush interval. The drive MUST guarantee coalescence — fire the N requests CONCURRENTLY (or rapid-fire on a single keep-alive connection) so their entries queue into the buffer FASTER than the interval elapses, and/or set the interval generously wide (e.g. `1s`–`2s`) relative to the burst duration — and confirm `maxBatchSize >= 2` holds over the 20/20 flake gate. A per-request round-trip that approaches the interval would let entries flush singly (`maxBatchSize == 1`, a false-negative flake); the PLAN pins a burst pattern + interval that keeps a comfortable margin.
- **Cross-side assertion (EXACT, aggregated over all received entries — AMEND-BUF-3 / AMEND-ALS-3):** for each of the N entries, the deterministic 7-field subset matches both sides (`request.{request_method, path[query-less], authority, user_agent}` + `response.{response_code, response_body_bytes}` + `protocol_version` == `HTTP11`). Plus `logs_written == N` on the subject (the entry counter is batch-invariant). NO cross-side message/stream/batch-count assertion (AMEND-BUF-3: reference per-worker fragmentation).
- **SUBJECT-side batching proof (the assertion that BITES against a 44.1-fixed-flush regression):** envoy-go produced ≥1 `StreamAccessLogsMessage` carrying ≥2 `HTTPAccessLogEntry`s (i.e. `maxBatchSize(subject) >= 2`, or equivalently `messageCount(subject) < N`). This is SUBJECT-side ONLY (the reference's batching is its own un-pinned per-worker business). It requires the receiver helper to expose per-message batch sizes (§8.2). A deliberate-break that reverts the sink to the 44.1 one-entry-per-message flush makes `maxBatchSize` collapse to 1 ⇒ this assertion FAILS (proving it LIVE).
- **UNasserted:** `common_properties.*`, the subject-absent reference fields, the `identifier.node` content, AND all stream/message/batch FRAMING on the REFERENCE side (D-ALS-BUFFER non-deterministic set).
- **Reachability:** the driver-owned in-process `accessloggrpc` receiver reachable from BOTH the subject (`127.0.0.1`) AND the reference (`host.docker.internal`), the `0081` precedent (D-ALS-RECEIVER-WIRING carries). NOTE the `reference_differential_fixture_dispatch_constraint` (one fixture dir = ONE runner branch) — `0082` is a single cross-side branch (no boot-reject prong), so one dir is correct.

## 13. ADR continuity — the ADR-0256 §Context DRAFT (anchored here; full entry lands at the 44.2 IMPL)
