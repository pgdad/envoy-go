**What this phase is.** Phase 44 is the **FIRST Observability-family row** — the first NEW feature family opened since the Upstream-robustness family (phases 39–43) closed at phase 43. It lands a streaming **gRPC Access Log Service (ALS) sink** — `envoy.extensions.access_loggers.grpc.v3.HttpGrpcAccessLogConfig` driving the `envoy.service.accesslog.v3.AccessLogService.StreamAccessLogs` client-streaming RPC — as a SECOND `accesslog.Sink` alongside the phase-06.2 file sink. It is the project's FIRST access-log sink that leaves the process (structured `HTTPAccessLogEntry` protos, not formatted text) and its SECOND gRPC-client consumer after ext_authz. It composes on two already-built substrates: the phase-06.2 access-log subsystem (the `accesslog.Sink` interface + the 10-field `Record` + the H1/H2 emit hooks) and the phase-18 `internal/grpcclient.Dialer` typed-wrapper layer (ADR-0158 — the `ALSClient` precedent). ZERO new packages, ZERO new go.mod modules anticipated (the ALS protos resolve at the pinned `go-control-plane/envoy v1.32.4`).

**The envelope (BRAINSTORM; a BY-CONCERN 3-leg split).**

- **44.1 — the core streaming sink** (ADR-0255): the `ALSConfig` parse arm (`HttpGrpcAccessLogConfig` TypeURL → cluster name + log_name; LIFTS gRPC ALS from the ADR-0041 silent-ignore set; HTTP-only + transport-V3-only; `tcp_logs`/non-V3 strict-rejected) + the `ALSClient` typed wrapper over `grpcclient.Dialer` + the `GrpcAccessLogSink` (the `AsyncFileSink` bounded-channel + writer-goroutine shape; stream lifecycle [lazy establish / identifier-once / reconnect-on-error]; the 10-field `Record`→`HTTPAccessLogEntry` structured mapping; a FIXED simple flush) + stats + `main.go` wiring + the `0081-grpc-access-log` differential (a NEW ALS gRPC receiver BackendKind 39). ANCHORS the Observability family.
- **44.2 — buffering** (ADR-0256): honor `buffer_size_bytes` + `buffer_flush_interval` (replace the 44.1 fixed flush with size+interval triggers) + an extended differential prong.
- **44.3 — header-capture** (ADR-0257): `additional_request_headers_to_log` + `additional_response_headers_to_log` (extend `accesslog.Record` + capture in the H1/H2 emit hooks by configured name) → map into `request.request_headers`/`response.response_headers` + an extended differential prong.

**Key BRAINSTORM decisions.** (Q0-family) the next family = **Observability** (over HTTP/3+QUIC [the most directly-composing but a heavy QUIC transport / likely the first new go.mod module in a long stretch], gRPC, xDS [the largest lift]). (Q0-subject) the first row = **gRPC ALS** (over stats sinks / tracing / tap — the cleanest extension of the `Sink` abstraction the project already owns + the most deterministic differential). (Q1-envelope) **Minimal + header-capture + buffering** (accept `log_name` + `envoy_grpc.cluster_name` + map the 10 `Record` fields + `additional_*_headers_to_log` + `buffer_size_bytes`/`buffer_flush_interval`; HTTP-logs-only + transport-V3-only fixed). (Q-split) **BY-CONCERN 3-leg** (core / buffering / header-capture — buffering is an independent flush-policy concern internal to the sink; header-capture touches a different subsystem, the `Record` + the emit hooks).

**The differential proof (a structured-proto receiver; wire-format-both-sides).** ONE fixture (44.1): `0081-grpc-access-log` — a NEW ALS gRPC receiver BackendKind 39 (an in-process `AccessLogServiceServer` accumulating the streamed `HTTPAccessLogEntry`s) that BOTH the reference Envoy and the subject stream to (the wire-format-both-sides discipline — both emit the SAME `StreamAccessLogsMessage` framing). The driver polls-to-converge until N entries arrive (a release barrier, NEVER a `time.Sleep`), then asserts the DETERMINISTIC structured-field subset cross-side EXACT (method/path/authority/protocol/response_code/user_agent; the non-deterministic `AccessLogCommon` fields left unasserted — the SPEC D-ALS-FIELDS pins exactly which). 44.2/44.3 extend `0081` with buffering/header prongs (or add dirs — a SPEC/PLAN call per `reference_differential_fixture_dispatch_constraint`).
