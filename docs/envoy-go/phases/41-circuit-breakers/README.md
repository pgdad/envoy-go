**What this phase is.** A per-priority `circuitBreaker` counter struct on `Cluster` (`internal/cluster/circuitbreaker.go`) parsed from `Cluster.circuit_breakers` (`cluster.v3.CircuitBreakers`, Cluster field 10); a synchronous, NON-BLOCKING `TryAcquireRequest()` at the router admission points (`doH1ClusterAction`/`doH2ClusterAction`, after `IncUpstreamRqTotal`, before the upstream call) + a `defer ReleaseRequest()` on completion (the overflow early-return precedes the defer → no double-release); on exhaustion a fail-fast `503` (the existing local-reply path) + `upstream_rq_pending_overflow`++ + `rq_open`=1. NO background goroutine; byte-identical when no `circuit_breakers` (a nil-guard, proven by the full 75-dir byte-stability gate held GREEN through every task).

**The `max_requests` keystone (scope narrowed from the BRAINSTORM trio).** The phase-41 BRAINSTORM settled "enforce the core overflow trio (`max_connections` + `max_pending_requests` + `max_requests`)"; the SPEC's §11 live pins NARROWED enforcement to the **`max_requests` keystone ONLY** (human-confirmed) because the reference's fail-fast `503/UO` comes ONLY from a request budget — `max_connections` is a soft throttle that PENDS rather than 503s, and `max_pending_requests` needs the connection-pool queue envoy-go's synchronous model lacks. `max_requests` maps EXACTLY onto envoy-go's model (clean cross-side parity); cx/pending enforcement is DEFERRED to the future per-protocol connection-pooling family row, their stat names registered emit-0 for parity.

**SPEC-firmed deltas (the §11 D-CB-* live pins + §1.1 amendments):**
- **AMEND-CB1** — `max_requests`-only enforcement; `max_connections`/`max_pending_requests` register-for-parity-but-defer.
- **AMEND-CB2** — a `max_requests` overflow increments `upstream_rq_pending_overflow` (the SAME counter `max_pending_requests` would use); there is NO `upstream_rq_overflow` (the two request budgets differ only by gauge `rq_open` vs `rq_pending_open`).
- **AMEND-CB3** — stat surface **+14 → 1163**: 10 per-priority `*_open` gauges (`cx_open`/`cx_pool_open`/`rq_open`/`rq_pending_open`/`rq_retry_open` × {default, high}) + 4 cluster overflow counters (`upstream_{cx,cx_pool,rq_pending,rq_retry}_overflow`), scoped to `circuit_breakers` clusters; only `default.rq_open` + `upstream_rq_pending_overflow` go LIVE, the other 12 emit 0 (deferred enforcement / deferred HIGH binding); `remaining_*` gauges DEFERRED (`track_remaining`-gated).
- **AMEND-CB4** — overflow ⇒ `503`; the reference also sets the `UO` flag + `upstream_reset_before_response_started{overflow}` details, but envoy-go has NO access-log response-flags plumbing (`ActionResponse` + the accesslog `Record` lack a flags field; the formatter hardcodes `RESPONSE_FLAGS` to `-`), so the `UO` flag is a RECORDED DEPARTURE (D-S41-3); the `0074` differential asserts the robust `503`-status + stats pair, never the access-log line.
- **AMEND-CB5** — effective defaults 1024/1024/1024/3/∞; `max_requests` defaults 1024 ⇒ the breaker is OFF unless explicitly small.
- **AMEND-CB6** — the PGV reject surface is THIN: envoy-go mirrors the 2 reference PGV rejects (`priority` enum-range + `retry_budget.budget_percent ∈ [0,100]`) + adds its OWN strict duplicate-priority reject (ADR-0080) + silent-ignores `per_host_thresholds`; NO new fuzzer (config-parse, not wire-decode).
- **AMEND-CB7** — +1 BackendKind `BlockingHoldResponder` (35 → 36 — holds a request on a re-armable gate freed by `GET /__release`) for the deterministic budget-fill.

**The differential proof.** `0074-circuit-breaker-max-requests` (cross-side, +1 BackendKind): fill the `max_requests` budget with N=4 held-open concurrent requests (the `BlockingHoldResponder`), poll `circuit_breakers.default.rq_open == 1` on BOTH sides (the subject AND `contrib-v1.37.2`), fire the 5th request ⇒ cross-side `503` + `upstream_rq_pending_overflow` delta + `rq_open` parity, then release via the backend `/__release` control port + drain (poll `rq_open → 0`). SLEEPLESS (the release barrier + poll-to-converge — NO `time.Sleep`); sequential-per-side (the shared in-process backend is idle between sides). 2 `-count=1` deliberate breaks (A: `tryAcquire` always-true ⇒ `rq_open` never converges; B: skip the overflow stat ⇒ the overflow-delta assertion fails) + 20/20 flake-free.
