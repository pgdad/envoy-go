**What this phase is.** Phase 38.2 lands `RouteAction.weighted_clusters` routing — the project's **FIRST per-request cluster-SELECTION primitive** — plus `WeightedCluster.ClusterWeight.metadata_match`, the per-weighted-cluster subset match that COMPOSES with the 38.1 subset LB. **SPEC-firmed deltas (vs the BRAINSTORM anticipations):** (D-WC1) `total_weight` is **DEPRECATED** upstream — the client uses the SUM of cluster weights; envoy-go IGNORES it (no total-vs-sum cross-check, no reject on mismatch). **The architecture (SPEC §3).** A new `weightedClusterRouteAction` (the `clusterRouteAction` sibling) holds N entries (each `{cluster, weight, subsetMatch}` — the subsetMatch is the route-level `metadata_match` ⊕ the entry's `ClusterWeight.metadata_match`, entry precedence, merged ONCE at config-build) + the route-level `hashPolicies` (shared) + a per-action `weightedSelector` (a `newPCGRNG()` draw `rng() % Σweight` + a cumulative walk — the `randomLB` model lifted to the router layer). It satisfies the UNCHANGED `routeAction` interface and, per request, picks an entry then runs the EXISTING `doH1ClusterAction`/`doH2ClusterAction` with the chosen entry's cluster + subsetMatch — a SELECTION primitive layered ON the 38.1 dispatch, NO `loadBalancer.Pick` change, NO exported-cluster change.

**The differential proof (per-side weight-distribution band; the `0060-lb-random` lineage).** ONE fixture (38.2): `0065-weighted-clusters` — an HTTP listener with a `weighted_clusters` route over 3 clusters on BOTH sides. Asserts a PER-SIDE distribution band (each cluster's `upstream_rq_total` within ~4–5σ of N · weight/Σweight — per-side because the independent per-request RNG makes cross-side per-request identity infeasible for a randomized policy, the `reference_differential_band_sigma_margin` discipline) + a metadata_match-composition arm (subset affinity within a chosen subset cluster — the 38.1 compose) + cross-side conservation (the sum of per-cluster `upstream_rq_total` = N, cross-equal) + a `/health` byte-equiv stream. **NO new BackendKind** (the `0063`/`0064` `HTTPEcho` reused; tail stays 33), **NO new fuzzer** (no wire decode; a selection-distribution property test is unit-level; fuzzers stay 42). Every leg proven live via `-count=1` deliberate-breaks (swap-weights → distribution fails; drop-a-cluster → conservation fails; drop-the-compose-metadata_match → composition fails).
