## 42.1 — what this leg is (DONE)

HTTP retries (`RouteAction.retry_policy` / `VirtualHost` field-16 fallback) as a re-attempt loop **WRAPPING** the existing single-attempt driver. A route configured with `retry_policy` re-attempts a failed upstream request against an LB-re-picked host: a `retryExecutor` classifies the buffered `ActionResponse.Status` against a parsed `retry_on` bitset and, on a retriable outcome with `num_retries` + `retry_budget` slots remaining, sleeps an exponential full-jitter backoff, replays the already-buffered request body, and re-invokes `doH{1,2}ClusterAction`. **Byte-identical when no `retry_policy`** (a nil-guard — the 76-subtest differential is the regression anchor).

**The architecture (ADR-0249).** A `retryExecutor` in `internal/filter/http/router/retry.go`:

- **The classifier** — the `retry_on` tokenizer + the `retryOnBits` bitset + `matches(status, localOrigin)`. `localOrigin` distinguishes a SYNTHESIZED connect/reset failure from a 5xx RESPONSE (a `connect-failure` token does NOT retry a 502 response). The enforced subset is `{5xx, gateway-error, connect-failure, reset, retriable-status-codes (+ explicit `retriable_status_codes[]`)}`; `{retriable-headers, envoy-ratelimited, grpc-*}` parse-accept-but-defer; unknown tokens silently ignored (freeform, no PGV).
- **The policy** — `NewRetryPolicy` + the exponential full-jitter backoff (`base 25ms` / `max 10×base` defaults, sub-1ms rounds up to 1ms) + the `max_interval < base_interval` reject arm. `num_retries` default 1 (0 ⇒ no retries, valid; unbounded).
- **The parse seam** — the `retry_policy` parsed in `buildRouterAction` (`hcm/config.go`) with the `VirtualHost.retry_policy` fallback threaded `buildRouteTable`→`buildAction`→`buildRouterAction`, carried on `clusterRouteAction` (`hcm/actions.go`); the `rp *RetryPolicy` threaded through the `H{1,2}ClusterAction` signatures (`router.go` / `router_h2.go` / `router_weighted.go` / `actions.go`).
- **The loop** — `retryExecutorH1` + `retryExecutorH2` WRAP the single-attempt `doH{1,2}ClusterAction`, which ALREADY buffer the full `ActionResponse` + re-run CB admission (`TryAcquireRequest`) + `RecordUpstreamResult` per call, so BOTH circuit breaking and outlier detection observe EVERY attempt. The body replays from the ADR-0076 1 MiB buffer (the HCM 413s an over-cap body BEFORE the router, so the replay source is always ≤1 MiB — NO over-cap guard needed).
- **The stats** — the +5 `upstream_rq_retry*` counters (`upstream_rq_retry`/`_retry_success`/`_retry_limit_exceeded`/`_retry_backoff_exponential`/`_retry_backoff_ratelimited`) register SCOPED to retry-policy-bearing clusters via the lazy idempotent `Cluster.EnsureRetryStats()` (a departure — keeps non-retry clusters byte-stable; +5 per retry cluster).
- **The `retry_budget` activation** — a cluster-level `activeRetries atomic.Int64` + `tryAcquireRetry`/`releaseRetry` on the phase-41 `circuitBreaker` (`activeRetries < max(min_retry_concurrency, ⌈budget_percent% × activeRequests⌉)`; defaults 20%/3); on a failed try-acquire ⇒ no retry + `upstream_rq_retry_overflow`++ + `rq_retry_open`=1. Flips the 2 phase-41 emit-0 stats LIVE, distinct from the static-cap `upstream_rq_retry_limit_exceeded`.

**SPEC-firmed deltas (the §1.1 AMEND-RT1..7 + the §11 D-RT-* live pins):**
