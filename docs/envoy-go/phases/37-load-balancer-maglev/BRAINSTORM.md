### 2.3 The `table_size` primality posture: DEPARTURE-reject a configured non-prime *(Q1 → ADR-0238)*

**Decision:** A configured non-prime `table_size` is **DEPARTURE-rejected** fail-fast at config-build (the least_request choice_count / thrift AMEND-T7 / tcp_proxy `NewFilter` fail-fast lineage). Accepted: an unset `table_size` (→ default 65537), any prime ≤ 5000011, and the cap 5000011 (itself prime). Rejected: a configured composite `table_size` (≤ 5000011 but not prime). The exact reject wording is a SPEC empirical pin (D-M5; the byte-stable-reject ADR-0080 discipline).

**Rationale:** Maglev's permutation algorithm requires the table size `M` to be prime: each host's permutation is `(offset + j*skip) % M` with `skip ∈ [1, M-1]`, and only when `M` is prime is every `skip` coprime to `M` — guaranteeing each permutation is a full `M`-cycle that can reach every empty slot, so the populate loop fills all `M` entries and TERMINATES. A composite `M` can leave the populate loop unable to reach empty slots (a naive implementation would not terminate; the distribution degrades). Upstream's PGV validates ONLY `table_size ≤ 5000011` — it does NOT enforce primality (both the default 65537 and the cap 5000011 happen to be prime, so the documented defaults never exercise the footgun). The reference parse-ACCEPTS a composite `table_size` and produces undefined/degraded behavior. Silent acceptance would silently diverge from a faithful reproduction (and risk a non-terminating build) — so the project's fail-fast discipline rejects it explicitly, the same posture least_request took for its behavior-bearing deferred knobs. This is a RECORDED DEPARTURE (the reference accepts; envoy-go rejects).

### 2.5 Differential strategy: header-key NAT-transparent TRUE cross-side affinity + spread (the `0062` precedent) *(Q-differential → fixture envelope §6)*
