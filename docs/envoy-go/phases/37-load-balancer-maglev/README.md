**Key BRAINSTORM decision — the `table_size` primality DEPARTURE.** A configured non-prime `table_size` is DEPARTURE-rejected fail-fast at config-build (accept unset→default-65537 / any prime ≤ 5000011 / the cap 5000011). Maglev's permutation requires `M` prime: each host's `skip ∈ [1, M-1]` is coprime to a prime `M`, so every permutation is a full `M`-cycle that reaches every empty slot — the populate loop fills all `M` entries and TERMINATES. Upstream's PGV validates ONLY `table_size ≤ 5000011` (NOT primality; the default 65537 + the cap 5000011 are both prime, so the documented defaults never exercise the footgun) and parse-ACCEPTS a composite verbatim, producing undefined/degraded behavior. Silent acceptance would silently diverge (and risk a non-terminating build) — so the project's fail-fast discipline rejects it explicitly (the least_request DEPARTURE lineage). A RECORDED DEPARTURE.
