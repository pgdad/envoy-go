# Phase 40 — `outlier-detection` (passive upstream health)

**Status:** BRAINSTORM DONE (lifecycle-state 0 → 1 at this commit; `docs/envoy-go/phases/40-outlier-detection/BRAINSTORM.md`). The **SECOND Upstream-robustness-family row** — **passive** upstream health (`Cluster.outlier_detection`, `cluster.v3.OutlierDetection`, Cluster field 19): hosts that fail on REAL traffic are *ejected* from the LB-eligible set for a time-based interval, then automatically returned. The counterpart to phase-39 **active** health checks (probes). **Next → the phase-40.1 SPEC** (the `consecutive_5xx` keystone leg) OR a new subject. ALL counts UNCHANGED at this BRAINSTORM (stat surface **1132** / fixtures **70** / fuzzers **42** / BackendKind tail **34** / DECISIONS tail **ADR-0244**, next-free **ADR-0245**).

**What this phase is.** Phase 40 is the family's second row (the family opened at phase 39 with active health checks). It REUSES the phase-39 host health-state primitive — the ADR-0242 `clusterHealth`/`hostHealth` registry and the ADR-0243 build-time-injected health-aware LB pick — and adds ONE genuinely new seam: a per-request **upstream-outcome callback** from the router back to the cluster (today the router knows `(picked endpoint, resp.StatusCode)` at the `IncStatusClass` point but nothing threads that `(host, outcome)` pair back to a cluster-level recorder). Where active health *probes* hosts out-of-band, outlier detection *observes* the in-band request stream — the two are independent, composable health dimensions.

**The envelope (BRAINSTORM; a pre-authorized 40.1/40.2/40.3 by-detector-class split).**

- **40.1 — the keystone + the `consecutive_5xx` detector** (the load-bearing leg): the ejection-state dimension on `hostHealth` (`ejected`/`unejectAtNanos`/`ejectCount`/`consec5xx`, DISTINCT from the active-HC `healthy` bit — outlier recovery is TIME-based) + the passive seam `cluster.RecordUpstreamResult(ep, UpstreamResult{StatusCode, LocalOriginErr})` wired into the H1/H2 router paths (fires on EVERY request; forward-compatible) + the `consecutive_5xx` detector & ejection lifecycle (`base_ejection_time × num_ejections` linear backoff; `max_ejection_percent` cap; lazy time-based un-eject) + the LB-pick extension (`isHealthy → available = isHealthy && !isEjected`; byte-identical when no `outlier_detection`) + the registry-creation extension (clusters with `health_checks` OR `outlier_detection`) + the `0069-outlier-detection-consecutive-5xx` differential. ADR-0245 lands here. Anticipated **~250–450 prod LoC / ~12–16 tasks**.
- **40.2 — the other consecutive detectors** (deferred): `consecutive_gateway_failure` + `consecutive_local_origin_failure` + `split_external_local_origin_errors` (threads the connect/reset `LocalOriginErr` outcome through the already-built seam). Reuses the 40.1 lifecycle wholesale.
- **40.3 — the statistical detectors** (deferred): `success_rate` + `failure_percentage` + a NEW per-interval cross-host mean/stddev aggregation runtime (the first new outlier goroutine), gated by `*_minimum_hosts`/`*_request_volume`.

**Key BRAINSTORM decisions.** (Q-subject) the next subject = **outlier detection** (chosen over circuit breakers / retries+hedging / per-protocol connection pooling + the 3 now-unblocked health-gated LB candidates — it composes most directly with the phase-39 host health-state primitive). (Q-scope) **full** outlier detection (all detector variants). (Q-split) **3 legs by detector class** (the consecutive/statistical fault line; the finer keystone over a 2-leg split or a single flat phase). (Architecture, Approach A → ADR-0245) ejection is a SEPARATE per-host sub-state fed by the per-request seam; the LB filters on `available`; `isHealthy`/`membership_healthy` keep their 39.1 active-HC-only meaning; the `UpstreamResult` struct is forward-compatible so 40.2/40.3 don't re-touch the router (rejected: folding outlier outcomes into the same `healthy` bit — wrong time-based-vs-consecutive recovery semantics; a stats-poll observer — no per-host outcome stat to poll).

**The differential proof (traffic-driven ejection; a NEW determinism shape).** ONE fixture (40.1): `0069-outlier-detection-consecutive-5xx` — a cluster {2 healthy backends, 1 always-5xx backend} + `outlier_detection{consecutive_5xx, base_ejection_time, max_ejection_percent}`, on BOTH sides. The driver drives 5xx traffic to trigger ejection, POLLS `/stats` until `ejections_active` converges on both sides (no fixed `time.Sleep`; the `0066` poll-to-converge + warmup-until-stable + delta-counter pattern, `reference_health_check_propagation_warmup`), THEN asserts traffic concentrates on the 2 healthy hosts + cross-side `outlier_detection.ejections_*` parity. Likely **+1 BackendKind** (an always-5xx responder — D-OD-BACKEND). 2 `-count=1` deliberate breaks (detector no-ops → 5xx host stays in rotation; LB ignores `available` → same). A time-based un-eject/recovery arm is a candidate-defer (flake risk). NO new fuzzer (reads the existing HTTP status).
