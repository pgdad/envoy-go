**What this phase is.** A per-cluster DEFAULT-priority `connPool` struct (`internal/cluster/connpool.go` — a SIBLING to the phase-41 `circuitBreaker`; referenced from `circuitBreaker` as `pool *connPool`) implementing two interlocking mechanisms: (1) a `max_connections` HARD-CAP — a `sync.Mutex`-guarded `activeConns` counter with a try-acquire at every connection-creation boundary (`Cluster.Dial` raw-dial + the `AcquireH1` pool-MISS; a pool HIT reuses an already-counted conn and needs no permit); (2) a `max_pending_requests` BOUNDED WAIT-QUEUE — a FIFO slice of per-waiter BUFFERED cap-1 wake channels; at the cap the request goroutine PENDS, woken via a direct permit-handoff on `connWithGauge.Close` (`connDec` → `pool.releaseConn` → pop head + send) or on `PutIdleH1` idle-return (CLOSE-and-wake when a waiter is queued, routing BOTH wake sources through the single permit mechanism); ctx-cancel-while-pending re-locks + `removeWaiterLocked`, and if already dequeued drains the channel + gives the permit back (the raced-permit-never-leaks discipline). Queue-full emits a `cluster.IsConnPoolOverflow` sentinel that routes to a fail-fast **503** + `upstream_rq_pending_overflow` (the shared phase-41 counter). Byte-identical when no `circuit_breakers` (the full 79→80-dir differential is the regression anchor).

**The load-bearing departure (AMEND-CP1 / ADR-0252).** The reference's `max_connections` is a SOFT breaker (`cx_active` can exceed the cap with timing slop — `reference_max_connections_soft_breaker`); cross-side-EXACT connection-pool differentials are infeasible against it. envoy-go implements a CLEAN HARD-CAP + bounded-queue as a documented departure (ADR-0252). The `0078` differential proves robust cross-side parity on the OBSERVABLE contract (overflow counter delta ≥ 1, final `cx_open == 0`) + subject-exact precision on the hard-cap invariants.

**The stat surface.** +2 new CB-scoped shapes: `upstream_rq_pending_active` (gauge — live pending waiters) + `upstream_rq_pending_total` (counter — cumulative successful pend+wake cycles). 3 existing shapes ACTIVATED from emit-0: `circuit_breakers.default.cx_open` (gauge — live connections against the cap), `circuit_breakers.default.rq_pending_open` (gauge — live pending waiters, a mirror of `upstream_rq_pending_active` under the CB prefix), `upstream_cx_overflow` (counter — overflow 503s). No surface delta from activation (already registered in the 1181 baseline). Net: **1181 → 1183**.

**The differential proof.** `0078-connection-pool-max-connections` (cross-side; REUSE `BlockingHoldResponder` — NO new BackendKind; `refContainerListenerPort = 19167`): a staged drive — fill N=2 held connections (poll until `cx_open + cx_active == N`) → queue M=2 pending waiters (poll until `rq_pending_open + pending_active == M`) → fire J=2 oversubscribers (assert all J receive 503 fast, `upstream_rq_pending_overflow == J`) → sticky-release (the new `/__release_sticky` control path, re-arming the hold for the woken waiters, so post-release redials don't stall) → assert `cx_open == 0` at drain. Subject-exact invariants + cross-side robustness (overflow delta ≥ 1, `cx_open == 0`). 2 `-count=1` deliberate breaks (A: hard-cap disabled → `cx_open` never reaches N → saturation poll times out; B: queue-full disabled → oversubscribers hang instead of receiving 503) + 20/20 flake-free + `-race`-clean.
