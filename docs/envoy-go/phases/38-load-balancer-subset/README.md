# Phase 38 — `load-balancer-subset`

**Status:** BRAINSTORM DONE (lifecycle-state 0 → 1 at this commit; `docs/envoy-go/phases/38-load-balancer-subset/BRAINSTORM.md`). **Next → the phase-38 SPEC** (`superpowers:writing-plans` scoped to SPEC authoring — execute the §10 D-SS1..D-SS7 empirical pins live against the contrib reference + the v1.32.4 module cache + upstream v1.37.2 source, anchor the ADR-0239 + ADR-0240 §Context drafts, confirm the 38.1/38.2 ADR-0045 split disposition). The Load-balancing family stays OPEN — 3 candidates remain after 38 {locality-weighted LB, priority load balancing, panic thresholds} (all health-gated).

**What this phase is.** Phase 38 is the **FIFTH Load-balancing-family row** — and the family's **FIRST wrapper**. `Cluster.lb_subset_config` is NOT a `Cluster.LbPolicy` enum value (unlike the five incumbents — roundRobin/leastRequest/randomLB/ringHashLB/maglevLB); it is a wrapper triggered by the presence of `lb_subset_config`, that selects a subset of endpoints matching the route's `metadata_match` and then **delegates to the cluster's existing `lb_policy` as the child policy run within that subset**. Picked from the 4-candidate roster as **the only candidate decoupled from the absent health-checking boundary** (the other three — locality-weighted / priority / panic — are health-gated and belong after the Upstream-robustness family). subset LB is the FIRST LB construct to extend the `Endpoint` type (a new `Metadata` field — the first per-endpoint dimension beyond `Host:Port`) and the FIRST to build a new producer plane since ring_hash (the route `RouteAction.metadata_match`). 3 family candidates remain after 38.

**The envelope (BRAINSTORM; a pre-authorized 38.1/38.2 by-plane split).**

- **38.1 — subset LB on the HTTP `RouteAction.metadata_match` plane** (this leg): a `subsetLB` wrapper (built once at cluster construction; enumerate subsets per selector × distinct endpoint-metadata value-tuples; a child `loadBalancer` per subset via the existing policy factory — ALL five child policies supported, the hashKey passes through to a hash-policy child; resolve the route match → subset → delegate `child.Pick`; the cluster-level fallback {NO_FALLBACK/ANY_ENDPOINT/DEFAULT_SUBSET}) + the `Endpoint.Metadata` dimension (the `envoy.lb` namespace captured at `extractEndpoints`) + the manager wrap-after-switch (subset wraps the `lb_policy` child — NOT a new `case`) + the seam-input widening (`Pick(hashKey, hasHash, match, hasMatch)` + `WithSubsetMatch`/`subsetMatchFrom`) + the HTTP `RouteAction.metadata_match` producer (attached to `clusterRouteAction`) + the `0064-lb-subset` differential. ~250–400 prod LoC / ~10–14 tasks.
- **38.2 — weighted-cluster routing + `ClusterWeight.metadata_match`** (deferred): `RouteAction.weighted_clusters` is a NEW per-request weighted-cluster-selection primitive (the router resolves a single `*cluster.Cluster` per route today — `actions.go:201`); only once it exists can `WeightedCluster.ClusterWeight.metadata_match` feed a subset. Its own SPEC/PLAN/IMPL.

**Key BRAINSTORM decisions.** (Q1) the seam + child architecture = **a wrapper owning per-subset child LBs, ALL five children** (factory reuse makes "all children" barely harder than one; the hashKey passes straight through to a subset's hash-policy child); the seam EXTENDS with a SECOND pick-input (the resolved subset match — after ADR-0235's hash key), a seam BUILD → its own ADR. (Q2/Q2b) the producer plane = the HTTP `RouteAction.metadata_match` plane for 38.1, with the **weighted-cluster plane split to 38.2** because weighted-cluster routing does not exist yet (a hidden prerequisite the brainstorm surfaced — it is its own routing primitive). (§2.6) **NO lb_policy reject-text change** — subset is not an enum value, so the phase-34/35/36/37 doubly-hit reject-text-retarget lineage breaks; the reject surface shifts to `lb_subset_config` validation (D-SS1).

**The differential proof (static-config NAT-transparent TRUE cross-side; the `0063`/`0062` precedent).** ONE fixture (38.1): `0064-lb-subset` — an HTTP listener routing to a cluster with `lb_subset_config` over `envoy.lb`-tagged endpoints on BOTH sides; header/path-routed routes each carrying a `metadata_match` pinned to a subset. Asserts subset affinity (every served backend ∈ the expected subset, BOTH sides — the SET-membership property) + a fallback arm (a no-match route exercises the cluster `fallback_policy`) + cross-side byte-equivalence + a cross-side `StatsAsserter` (the `lb_subsets_*` stats + `upstream_rq_total` cross-equal). The `metadata_match` is STATIC route config → NAT-transparent → TRUE cross-side on BOTH arms (strictly cleaner than ring_hash's tcp source_ip leg). **NO new BackendKind** (the `0063` HTTP backends reused; tail stays 33), **NO new fuzzer** (no wire decode; a subset-resolution property test is unit-level; fuzzers stay 42). Every leg proven live via `-count=1` deliberate-breaks (drop-the-metadata_match → fails affinity; misroute-the-no-match → fails the fallback arm).
