## 1. Purpose / Mission

Deliver envoy-go's THIRD access-log sink that leaves the process (after the phase-06.2 file sink and the phase-44 gRPC ALS sink): when an HCM `access_log[]` entry carries an `OpenTelemetryAccessLogConfig` typed_config, envoy-go dials the configured `common_config.grpc_service.envoy_grpc.cluster_name` cluster (via the phase-18 `grpcclient.Dialer`) and BATCHES each access-log event into an OTLP `LogRecord` inside one `ExportLogsServiceRequest`, sent over the **UNARY** `opentelemetry.proto.collector.logs.v1.LogsService.Export` RPC. This is the project's THIRD concrete `accesslog.Sink` (alongside `AsyncFileSink` + `GrpcAccessLogSink`) and its FIRST consumer of an out-of-tree (non-`go-control-plane`) proto module (`go.opentelemetry.io/proto/otlp`, promoted transitive→direct). It composes on THREE already-built substrates — the phase-06.2 `Sink`/`Record` subsystem, the phase-18 `grpcclient` layer, and the phase-44 ALS sink/buffer/client machinery — adding ZERO new Go packages and exactly ONE new go.mod module. Byte-identical when no OTLP `access_log` entry is configured (the file + gRPC-ALS paths are untouched; the full differential is the regression anchor). It ANCHORS ADR-0258; the Observability family STAYS OPEN (tracing / stats sinks / tap remain future rows).

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-26, contrib-v1.37.2 — an H1 downstream → a real HTTP backend, with an HCM `access_log[]` `OpenTelemetryAccessLogConfig` exporting to an h2c OTLP `LogsService` receiver, all on a shared bridge per `reference_docker_probe_bridge_network`; **decode-ran proof: `access_logs.open_telemetry_access_log.logs_written: 13` for 13 requests + 13 captured `LogRecord`s in the receiver stdout**) drove these amendments. Several CORRECT the brainstorm's hypothesized mapping — the live OTLP built-in record is far LEANER than the brainstorm assumed.

- **AMEND-OTLP-BUILTINS (the built-in `LogRecord` is a BARE `time_unix_nano`; the "built-in labels" are 4 `Resource` attributes, NOT `LogRecord` attributes — the brainstorm's method/path/authority/`SeverityNumber` built-ins DO NOT EXIST).** Live finding (D-OTLP-BUILTINS): with no `body`/`attributes`/`resource_attributes` configured (the pure built-in record), the reference emits a `LogRecord` carrying ONLY `time_unix_nano` — NO `observed_time_unix_nano`, NO `severity_number`/`severity_text`, NO `body`, NO `LogRecord.attributes`. The only "built-in" content is FOUR `Resource.attributes` key/values: `log_name` (← `common_config.log_name`), `zone_name` (← `node.locality.zone`), `cluster_name` (← `node.cluster`), `node_name` (← `node.id`) — all four keys ALWAYS present (empty `stringValue` when the source is unset). This REPLACES the brainstorm §2.5 hypothesis (method/path/authority/protocol/response_code/upstream_host as built-in `KeyValue`s + a status→severity mapping): those are NOT built-ins — they require the 45.2 `attributes`/`body` command-operator templates. 45.1's built-in mapping is therefore exactly `Record.StartTime → LogRecord.time_unix_nano` PLUS the 4 `Resource` built-in labels.
- **AMEND-OTLP-DISABLE-BUILTIN (`disable_builtin_labels: true` drops ALL 4 `Resource` labels, all-or-nothing; the `LogRecord.time_unix_nano` is untouched).** Live finding (D-OTLP-BUILTINS, config B): with `disable_builtin_labels: true` the `Resource` becomes EMPTY (`{}`) — every one of the 4 built-in labels is dropped (not a named subset). The `LogRecord` still carries `time_unix_nano`. So `disable_builtin_labels` is CONSUMED at 45.1 (it gates the ONLY built-in content the leg emits) — a boolean all-or-nothing switch over the `Resource.attributes` block.
- **AMEND-OTLP-SEVERITY (NO severity mapping — `severity_number`/`severity_text` are NEVER set by the reference; D-OTLP-SEVERITY DISSOLVES).** Live finding (D-OTLP-SEVERITY): across 2xx responses the reference left `severity_number` at 0 (unset) and `severity_text` empty on every captured `LogRecord`. There is NO status-class→severity mapping in the built-in record (severity, if wanted, is an operator-templated 45.2 concern, not a built-in). 45.1 sets NEITHER field. This RETIRES the brainstorm's hypothesized `ResponseCode → SeverityNumber` mapping.
- **AMEND-OTLP-STATS (the prefix is `access_logs.open_telemetry_access_log.*`, NOT the brainstorm's `access_logs.open_telemetry.*`; +2 STATIC; `stat_prefix` injects an infix — DEFERRED parse-accept-but-inert at 45.1).** Live finding (D-OTLP-STATS): the sink-specific stats are exactly two process-global counters `access_logs.open_telemetry_access_log.{logs_written,logs_dropped}` (`logs_written: 13` for 13 records — batch-INVARIANT, == total records handed to the sink, NOT `Export`-call count; `logs_dropped` stayed 0). With `stat_prefix: myprefix` set, the names become `access_logs.open_telemetry_access_log.myprefix.{logs_written,logs_dropped}` (an OPTIONAL infix between the static prefix and the leaf). 45.1 pins the two FIXED names (the no-`stat_prefix` form) and treats `stat_prefix` as PARSE-ACCEPT-but-INERT (the 44.1 phased-rollout discipline; the differential sets no `stat_prefix` ⇒ behavior matches). Surface **1189 → 1191** (+2). STATIC names (no `IsValidName` guard at 45.1 since the dynamic-infix path is deferred — `reference_dynamic_stat_name_charset_guard` applies only when `stat_prefix` honoring lands).
- **AMEND-OTLP-EXPORT-SHAPE (one `ResourceLogs` → one EMPTY-scope `ScopeLogs` → N `LogRecord`s per `Export`; the `Resource` carries the built-in labels; framing legitimately varies — assert the PAYLOAD, not framing).** Live finding (D-OTLP-EXPORT-SHAPE): each `ExportLogsServiceRequest` carried exactly one `ResourceLogs` with `resource.attributes` = the built-in labels and one `ScopeLogs` whose `scope` is ABSENT (no `name`/`version`) holding the `LogRecord`s. Under low concurrency the reference still BATCHED (13 requests → 12 `Export` calls; one call carried 2 records) and opened roughly one fresh upstream H2 connection per `Export` (`upstream_cx_total: 12`). Per `reference_streaming_sink_differential_framing` + `reference_wire_format_both_sides_see_same_bytes`, the `0084` differential asserts the aggregated per-`LogRecord` payload (the `Resource` built-in labels + `time_unix_nano` presence + record count), NOT `Export`-call count / per-call batch sizes / connection count (all of which legitimately vary side-to-side).

### 3.3 The `OTLPAccessLogSink` (`internal/accesslog` — the `GrpcAccessLogSink` shape, unary-batch flush)

A THIRD concrete `accesslog.Sink` (`accesslog.go:18`) alongside `AsyncFileSink` + `GrpcAccessLogSink`, mirroring the bounded-channel + writer-goroutine + size/interval/close BUFFER + idempotent-`Close` pattern (`grpcsink.go:48`/`:166`), but flushing via the UNARY `Export` of a batch of `LogRecord`s:

- **Sink-facing client seam (the `alsClient` `:22` precedent):** define a minimal `otlpClient interface { Export(ctx, *collogspb.ExportLogsServiceRequest) (*collogspb.ExportLogsServiceResponse, error); Close() error }` in `internal/accesslog` so the sink is test-fakeable and need not import `grpcclient` (no import cycle; `*grpcclient.OTLPLogsClient` satisfies it structurally).
- **Fields (the `GrpcAccessLogSink` `:48` shape):** `ch chan any` (capacity `defaultChannelCapacity` 4096); the `otlpClient`; `logName string`; `node *corev3.Node` (for the Resource built-in labels); `disableBuiltinLabels bool`; the two `*stats.Counter` (`logsWritten`/`logsDropped`); `done chan struct{}`; `closeOnce sync.Once`; `closeErr error`; `lastDropLog atomic.Int64`; `bufferSizeBytes int`; `bufferFlushInterval time.Duration`; `ctx`/`cancel` (bounded shutdown — the `:74` precedent).
- **`Submit(r any)`** — NON-blocking drop-newest (the `grpcsink.go` Submit shape): `select { case ch <- r: default: logsDropped.Inc(); <rate-limited diag> }`. Ignores any non-`*Record`.
- **The writer goroutine (`run`):** drains the channel; builds a `*logspb.LogRecord` from each `*Record` (§3.4); ACCUMULATES `LogRecord`s into an in-memory buffer; FLUSHES the batch on the FIRST of three triggers (the 44.2 machinery): the accumulated serialized bytes (`sum of proto.Size(logRecord)`) reaching `bufferSizeBytes` (0 ⇒ flush-every-entry), the `bufferFlushInterval` ticker, or `Close` draining the pending buffer. A flush builds ONE `*collogspb.ExportLogsServiceRequest{ ResourceLogs: [ one ResourceLogs ] }` (§3.5) and calls `client.Export(ctx, req)`. `logsWritten` counts ENTRIES (batch-INVARIANT == records, AMEND-OTLP-STATS), incremented `logsWritten.Add(len(batch))` once the batch is successfully `Export`ed (the 44.2 count-on-flush precedent — under the `0084` no-outage path this equals N; the IMPL pins the count-on-successful-flush semantics so a sustained-outage drop is NOT counted as written). On an `Export` error: log, re-dial is NOT needed (the `ClientConn` self-heals; a unary RPC has no stream to re-open) — retry the batch once; on a second failure drop the batch logged-not-counted (bounded memory under a sustained outage; those records are NOT counted in `logs_written`). NO identifier-once, NO stream — strictly simpler than `GrpcAccessLogSink.run()`.
- **`Close()`** — `sync.Once`-guarded (the `grpcsink.go` Close shape): close the channel, await `done` (bounded by `closeDrainGrace` + `cancel`), then `client.Close()`. Idempotent + threadsafe.
- **No `Formatter`** — OTLP emits a structured proto (the `format.go` text abstraction is file-sink-only; 45.2's operator engine is a NEW subsystem, not `format.go`).

> **Reuse boundary (honest):** `GrpcAccessLogSink.run()` (`grpcsink.go:166`) is tied to the client-STREAMING `StreamAccessLogs` (identifier-once, `stream.Send`, `CloseAndRecv`) and builds `HTTPAccessLogEntry`. The OTLP sink MIRRORS its channel + buffer-trigger LOOP shape but is a PARALLEL implementation (different entry type `LogRecord`, different flush call `Export`, no stream lifecycle). The buffer-trigger logic (size-sum / ticker / close-drain) is the conceptual reuse; the PLAN decides whether any of it factors into a shared helper or is re-expressed.

### 3.5 The `Resource` built-in labels + the Export envelope (§11 D-OTLP-BUILTINS/EXPORT-SHAPE)

A flush builds one `ExportLogsServiceRequest`:
```
ExportLogsServiceRequest{
  ResourceLogs: [ ResourceLogs{
    Resource:  resourcepb.Resource{ Attributes: <built-in labels, unless disableBuiltinLabels> },
    ScopeLogs: [ ScopeLogs{ LogRecords: <the batch> } ],   // Scope ABSENT (no name/version)
  } ],
}
```
- **The 4 built-in `Resource.attributes`** (typed-import `commonpb "go.opentelemetry.io/proto/otlp/common/v1"` for `KeyValue`/`AnyValue`; `resourcepb "go.opentelemetry.io/proto/otlp/resource/v1"`), in order — ALWAYS all 4 keys, empty `stringValue` when the source is unset (AMEND-OTLP-BUILTINS):
  - `log_name` ← `OTLPConfig.LogName`
  - `zone_name` ← `node.GetLocality().GetZone()`
  - `cluster_name` ← `node.GetCluster()`
  - `node_name` ← `node.GetId()`
- **`disableBuiltinLabels == true`** ⇒ omit the entire `Resource.attributes` block (an EMPTY `Resource`; AMEND-OTLP-DISABLE-BUILTIN). The `LogRecord.time_unix_nano` is unaffected.
- **`ScopeLogs.scope`** is ABSENT (the reference populated no `name`/`version`); envoy-go leaves it nil.
- **Node source (D-OTLP-NODE, §12):** the Resource labels source from envoy-go's bootstrap node. `main.go:132` currently builds a MINIMAL `&corev3.Node{Id, Cluster}` (no locality) for the ALS sink; 45.1 needs `node.locality.zone` too, so the OTLP wiring sources the labels from `bs.Proto.GetNode()` directly (`GetId`/`GetCluster`/`GetLocality().GetZone()`) — `zone_name` is empty when no locality is configured (matching the reference's empty `zone_name`). The exact node plumbing (reuse the `main.go:132` `*corev3.Node` vs. read locality at the OTLP pass) is a PLAN detail.

### 3.6 Boot wiring (`cmd/envoy-go/main.go`)
