## 1. Purpose / Mission

Make envoy-go's OTLP access logger emit OPERATOR-TEMPLATED content. 45.1 shipped the LEAN built-in record (a bare `time_unix_nano` + the 4 `Resource` built-in labels) and STRICT-REJECTED any configured `body`/`attributes`/`resource_attributes`. 45.2 lifts that reject: when an `OpenTelemetryAccessLogConfig` carries a `body` (an `AnyValue`) and/or `attributes` (a `KeyValueList`), envoy-go substitutes the Envoy command operators (`%REQ(:METHOD)%`, `%RESPONSE_CODE%`, `%START_TIME%`, …) against each access-log `Record` and emits the result as `LogRecord.body` / `LogRecord.attributes`; a configured `resource_attributes` (a `KeyValueList`) is emitted as extra `Resource.attributes` alongside (or, with `disable_builtin_labels`, instead of) the 4 built-in labels. Because Envoy's substitution-format operator set is vast (dozens of `StreamInfo` fields) while envoy-go's proto-agnostic `Record` carries ~10 scalar fields, 45.2 supports a CURATED operator subset (the operators that map 1:1 to `Record` fields — exactly the `format.go` `Default()` file-formatter roster) and STRICT-REJECTS every operator outside it at parse time. This is the envoy-go-strict mirror of the reference's own behavior: the reference BOOT-REJECTS a truly-invalid operator (`%FOOBAR%` → "Not supported field in StreamInfo: FOOBAR") and ACCEPTS valid-but-out-of-`Record` operators (`%UPSTREAM_CLUSTER%` → "backend"); envoy-go rejects BOTH classes, a documented departure (some valid-Envoy operators boot-reject in envoy-go). 45.2 adds ZERO new Go packages, ZERO new go.mod modules. Byte-identical when no OTLP `access_log` entry carries `body`/`attributes`/`resource_attributes` (the 45.1 built-in path is untouched; the `0084` fixture is the regression anchor). It ANCHORS ADR-0259 and is the FINAL leg of the SECOND Observability-family row — its IMPL flips ROADMAP row 45 → `done`; the Observability family STAYS OPEN (tracing / stats sinks / tap remain future rows).

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-26, contrib-v1.37.2 — an H1 downstream → a real HTTP backend, an HCM `access_log[]` `OpenTelemetryAccessLogConfig` with `body`/`attributes`/`resource_attributes` exporting to an h2c OTLP `LogsService` receiver, all on a shared bridge per `reference_docker_probe_bridge_network`; **decode-ran proof: every fired request produced a captured `LogRecord` with the substituted `body`+`attributes` in the receiver stdout**) drove these pins. Several REFINE the SPEC-45.1 §11 D-OTLP-OPERATORS incidental note.

- **AMEND-OPS-1 (`body` + `attributes` are PER-RECORD command-operator-templated; `resource_attributes` are NOT request-substituted — they pass request operators through LITERALLY).** Live finding (D-OTLP-2-OPERATORS): `body.string_value: "%REQ(:METHOD)% %REQ(:PATH)% %PROTOCOL% %RESPONSE_CODE%"` → `LogRecord.body.stringValue = "GET /api/widgets?x=1 HTTP/1.1 200"`; each `attributes` value operator resolved per-record (`op_method`→"GET", `op_response_code`→"200", …). BUT a `resource_attributes` value `"%REQ(:AUTHORITY)%"` emitted the LITERAL string `"%REQ(:AUTHORITY)%"` (NOT substituted) — `Resource.attributes` are built ONCE per logger (resource scope), so request operators have no per-record meaning there. 45.2 therefore applies the operator engine ONLY to `body`+`attributes`; `resource_attributes` are emitted VERBATIM (literal copy; resource-scoped operators like `%ENVIRONMENT(...)%` are out-of-scope and pass through literally — envoy-go does not substitute them).
- **AMEND-OPS-2 (all substituted values are STRING — no typed-int inference; config `AnyValue` must be `string_value` / `kvlist_value` / `array_value` only — `int_value`/`bool_value` BOOT-REJECT).** Live finding (D-OTLP-2-ANYVALUE-TYPING): even a single-operator value (`%RESPONSE_CODE%` → `{"stringValue":"200"}`, `%DURATION%` → `{"stringValue":"0"}`) emits a `stringValue` — there is NO single-operator typed-int promotion. A config value of `int_value: 42` / `bool_value: true` BOOT-REJECTS with `error 'Only string values, nested key value lists and array values are supported in OpenTelemetry access log format.'`. So the config `AnyValue` value-type roster is exactly `{string_value, kvlist_value, array_value}`; envoy-go MIRRORS the boot-reject for `int_value`/`bool_value`/`double_value`/`bytes_value`. Structured `kvlist_value`/`array_value` config is preserved STRUCTURALLY with each `string_value` LEAF operator-substituted (recursively — see AMEND-OPS-3). Every substituted leaf is emitted as `stringValue`.
- **AMEND-OPS-3 (`body` and each `attributes` value may be `string` OR a nested `kvlist`/`array`, recursively operator-substituted at the leaves).** Live finding: `body.kvlist_value{b_method:"%REQ(:METHOD)%", b_code:"%RESPONSE_CODE%"}` → `LogRecord.body.kvlistValue` with each leaf substituted (`b_method`→"GET", `b_code`→"200"); an `attributes` value `array_value:["%REQ(:METHOD)%", "literal-elem"]` → `arrayValue:["GET","literal-elem"]`; an `attributes` value `kvlist_value{inner_method:"%REQ(:METHOD)%"}` → nested `kvlistValue` substituted. So the engine walks the `AnyValue` tree and substitutes every `stringValue` leaf, preserving the `kvlist`/`array` structure.
- **AMEND-OPS-4 (the SUPPORTED operator subset = the operators that map 1:1 to `Record` fields; STRICT-REJECT every other operator at parse, including valid-Envoy ones).** Live finding (D-OTLP-2-UNKNOWN-OP): a truly-invalid operator `%FOOBAR%` BOOT-REJECTS ("Not supported field in StreamInfo: FOOBAR"); a valid-but-out-of-`Record` operator `%UPSTREAM_CLUSTER%` is ACCEPTED by the reference (→ "backend"). envoy-go's `Record` (`accesslog.go:29`) carries `{StartTime, Method, Path, Protocol, ResponseCode, BytesSent, Duration, Authority, UserAgent, UpstreamHost}` (+ the 44.3 capture maps). The 45.2 curated supported set is the `format.go` `Default()` roster mapping to those fields: `%START_TIME%`, `%REQ(:METHOD)%`, `%REQ(:PATH)%`, `%REQ(:AUTHORITY)%`, `%REQ(USER-AGENT)%`, `%PROTOCOL%`, `%RESPONSE_CODE%`, `%BYTES_SENT%`, `%DURATION%`, `%UPSTREAM_HOST%`. Every operator OUTSIDE this set (incl. `%RESPONSE_FLAGS%`, `%BYTES_RECEIVED%`, `%RESP(...)%`, arbitrary `%REQ(<non-UA-non-pseudo>)%`, `%UPSTREAM_CLUSTER%`, `%DOWNSTREAM_*%`, …) is STRICT-REJECTED at parse (a boot error) — the envoy-go-strict mirror of the reference's own unknown-operator boot-reject; a documented departure that some valid-Envoy operators boot-reject in envoy-go (NOT a silent `-`).
- **AMEND-OPS-5 (`resource_attributes` are appended AFTER the 4 built-in labels and SURVIVE `disable_builtin_labels:true` — independent).** Live finding (D-OTLP-2-RESOURCE-MERGE): `Resource.attributes` order is `[log_name, zone_name, cluster_name, node_name, <resource_attributes…>]`; with `disable_builtin_labels: true` the 4 built-ins drop but `resource_attributes` REMAIN (Resource = just the `resource_attributes`). So `disable_builtin_labels` gates ONLY the 4 built-in labels (45.1's AMEND-OTLP-DISABLE-BUILTIN), NOT `resource_attributes`. The 45.1 `buildResource` (which returned an EMPTY `Resource{}` under `disableBuiltinLabels`) must be extended to ALWAYS append `resource_attributes` regardless of the flag.
- **AMEND-OPS-6 (`%REQ(:PATH)%` carries the full path WITH query on the reference; envoy-go's H1 `Record.Path` STRIPS the query — a documented departure; the `0085` cross-side EXACT differential uses a query-less path).** Live finding: `%REQ(:PATH)%` for `/foo/bar?q=1` → `"/foo/bar?q=1"` (query included). envoy-go's H1 emit hook sets `Path: r.URL.Path` (`accesslog_emit.go:26` — query STRIPPED by `net/url`), while the H2 hook sets `Path: req.Path` (`:path` pseudo-header — query INCLUDED). So `%REQ(:PATH)%` is SUPPORTED but cross-side-EXACT only for a query-less path under H1 (the pre-existing `Default()` limitation; same as the file sink). The `0085` differential uses a query-less path. A missing request header (`%REQ(X-MISSING)%`) emits the literal `-` (Envoy missing-value dash) — but arbitrary `%REQ(<name>)%` beyond USER-AGENT is STRICT-REJECTED at parse (AMEND-OPS-4), so the missing-value path is only reachable for the supported header operators (USER-AGENT present-or-empty).

The 44.3 capture maps (`Record.RequestHeaders`/`ResponseHeaders`) hold only the CONFIGURED `additional_*_headers_to_log` names; wiring the operator engine to drive header capture (so `%REQ(X-FOO)%` auto-captures `x-foo`) is a documented follow-on. 45.2 supports only the fixed header operator `%REQ(USER-AGENT)%` (the one header field on `Record`).
- **`formatters`** (the `[]TypedExtensionConfig` custom-formatter-extension field) — STAYS STRICT-REJECTED (D-OTLP-2-FORMATTERS; always out of scope — no extension-formatter framework in envoy-go).

- **Resource-scoped operators in `resource_attributes`** (e.g. `%ENVIRONMENT(...)%`) — pass through LITERALLY (AMEND-OPS-1; `resource_attributes` are emitted verbatim, no substitution). Not a deferral — an absence matching the request-operator pass-through the reference exhibits.

- **`severity_number` / `severity_text`** — STILL never populated (45.1 AMEND-OTLP-SEVERITY; no operator templates them in the curated set; if an operator-driven severity is ever wanted it is a future follow-on).

### 3.1 The operator engine (`internal/accesslog/otlpformat.go` — NEW; no existing engine to reuse)

> **Honest reuse finding:** there is NO existing parameterized command-operator engine to reuse. The phase-06.2 file formatter (`format.go` `Default()`) is a HARD-CODED single-format function (its 15 operators are inlined at fixed positions; `log_format`/`format_string` is REJECTED per ADR-0067). 45.2 builds a NEW small engine. It REUSES the operator SEMANTICS (the same `Record`-field → operator mapping + the `%START_TIME%` format `2006-01-02T15:04:05.000Z` + the `%DURATION%` = `Duration/1e6` ms + the missing-value `-`) and the `Record` struct itself; it does NOT reuse `Default()`'s body (which is non-parameterized). Note OTLP values are PROTO strings — NO CSV/quote escaping (the `format.go` `escape()` is file-sink-only).

A two-phase design (compile-once at boot, substitute-per-record at runtime):

- **Operator registry** — a map from the supported operator TOKEN to a `func(*Record) string` extractor. The curated set (AMEND-OPS-4):
  | operator token | `Record` field | runtime value |
  |---|---|---|
  | `%START_TIME%` | `StartTime` | `StartTime.UTC().Format("2006-01-02T15:04:05.000Z")` |
  | `%REQ(:METHOD)%` | `Method` | verbatim |
  | `%REQ(:PATH)%` | `Path` | verbatim (H1 query-stripped — AMEND-OPS-6) |
  | `%REQ(:AUTHORITY)%` | `Authority` | verbatim |
  | `%REQ(USER-AGENT)%` | `UserAgent` | `UserAgent` or `-` if empty (missing-value dash) |
  | `%PROTOCOL%` | `Protocol` | verbatim |
  | `%RESPONSE_CODE%` | `ResponseCode` | `strconv.Itoa` |
  | `%BYTES_SENT%` | `BytesSent` | `strconv.FormatInt` |
  | `%DURATION%` | `Duration` | `strconv.FormatInt(int64(Duration/1e6), 10)` (ms) |
  | `%UPSTREAM_HOST%` | `UpstreamHost` | verbatim or `-` if empty |
  (The PLAN finalizes the exact missing-value/`-` disposition per operator against the §11 probe — D-OTLP-2-SUPPORTED-SET-FINAL; the table above is the as-probed reference behavior.)
- **Compile (boot)** — `CompileOTLPTemplate(s string) (*otlpTemplate, error)`: scan `s` for `%…%` operators (the Envoy `%`-delimited grammar; `%%` is a literal `%`), splitting into a slice of segments `{literal | operatorFn}`. STRICT-REJECT (return an error) any `%…%` token NOT in the registry — this is the boot-reject that the bootstrap parse arm surfaces. A pure-literal string compiles to a single literal segment (zero operators).
- **Compile the `AnyValue` tree** — `CompileOTLPValue(v *commonpb.AnyValue) (*otlpValueTemplate, error)`: walk the config `AnyValue`; for a `string_value` compile its template; for a `kvlist_value`/`array_value` recurse; for ANY OTHER value-type (`int_value`/`bool_value`/`double_value`/`bytes_value`) return a type error (the AMEND-OPS-2 boot-reject mirror). Produces a compiled tree mirroring the `AnyValue` structure.
- **Substitute (per-record)** — `(*otlpValueTemplate).Eval(rec *Record) *commonpb.AnyValue`: walk the compiled tree, emit a `stringValue` for each compiled string leaf (concatenating literal + extractor segments), preserving `kvlist`/`array` structure. Pure-allocation, no I/O.

> **Exported-type note (tracks D-OTLP-2-COMPILE-SITE):** the type names above (`otlpTemplate`/`otlpValueTemplate`) are illustrative-unexported. If bootstrap compiles at parse (the §3.2 RECOMMENDED site), the compiled types MUST be EXPORTED (`OTLPTemplate`/`OTLPValueTemplate`) so an `OTLPConfig` field can name them (and to avoid the golangci-lint exported-returns-unexported nit, `feedback_pertask_gofmt_lint`). If instead bootstrap threads raw proto and the sink compiles, the types stay unexported. The PLAN settles this with D-OTLP-2-COMPILE-SITE.

### 3.2 Config parse — lift the STRICT-REJECT arms (`internal/bootstrap/bootstrap.go`)

The 45.1 `parseOpenTelemetryAccessLog` (`bootstrap.go:475`) STRICT-REJECTS `body` (`:480`), `attributes` (`:483`), `resource_attributes` (`:486`); `formatters` (`:489`) STAYS rejected. 45.2:
