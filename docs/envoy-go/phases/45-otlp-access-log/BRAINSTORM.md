## 2. Design decisions

### 2.1 Subject confirmation: the Observability family's SECOND row is the OTLP access logger *(Q0 → phase 45 row registered)*

The OTLP access logger (over tracing, stats sinks, tap). Rationale: it REUSES the phase-44 sink/buffer/client machinery almost wholesale (the `common_config` is the SAME `CommonGrpcAccessLogConfig` proto message), it is canonical Envoy + canonical OpenTelemetry, and its structured-`LogRecord` differential is the most deterministic of the remaining Observability surfaces.

### 2.2 Envelope: built-in `LogRecord` mapping + a command-operator engine *(Q1 → the full accept set)*

Map the `Record` (+ header maps) into the built-in `LogRecord` (`TimeUnixNano`/`SeverityNumber`/built-in attributes; `disable_builtin_labels` honored) PLUS a minimal `%…%` substituter populating `body`/`attributes`/`resource_attributes`. Chosen over built-ins-only. HTTP-only; transport-V3-only; strict-reject `google_grpc`/V2/`formatters`.

### 2.3 Split axis: by-concern, 45.1 (core + built-ins + buffering) → 45.2 (the command-operator engine) *(Q-split → ADR-0258 + ADR-0259)*

By-concern over flat or 3-leg. Buffering FOLDS into 45.1 (it is the reused 44.2 `CommonGrpcAccessLogConfig` buffer path — no independent work); the operator engine is split out as its OWN leg because it is a genuinely new (small) `%…%` template subsystem touching a different concern than the built-in sink. Each leg lands a working, differential-provable sink.

### 2.4 The sink lifecycle: lazy dial, unary batched Export, reconnect-on-error *(self-answered; pinned at SPEC, D-OTLP-EXPORT-SHAPE)*

The `OTLPAccessLogSink` mirrors `GrpcAccessLogSink`'s bounded-channel + writer-goroutine + buffer shape (`grpcsink.go:166`): `Submit` is non-blocking (drop-newest on channel-full, incrementing `logs_dropped`); the writer goroutine drains the channel, accumulates `LogRecord`s into a buffer, and flushes a BATCH on EITHER the `buffer_size_bytes` byte-sum OR the `buffer_flush_interval` timer (the reused 44.2 trigger) by calling `OTLPLogsClient.Export(ctx, req)` with one `ExportLogsServiceRequest`; on an `Export` error it re-dials lazily (the unary RPC has NO stream lifecycle / NO identifier-once — simpler than ALS). `Close` is idempotent (the `sync.Once` precedent) + flushes the buffer before the final `Export`.

### 2.5 The structured mapping: the `Record` → built-in `LogRecord` *(self-answered; pinned at SPEC, D-OTLP-BUILTINS)*

The proto-agnostic `Record` maps into a built-in `LogRecord`: `StartTime → TimeUnixNano` (+ `ObservedTimeUnixNano`); `ResponseCode → SeverityNumber` (a status-class→severity mapping, D-OTLP-SEVERITY); the Envoy built-in attributes (method/path/authority/protocol/response_code/upstream_host/... as `KeyValue`s) gated by `disable_builtin_labels`. The SPEC live-probe pins the EXACT built-in attribute key set + the `disable_builtin_labels` effect + the `ResourceLogs`/`ScopeLogs`/`Resource` nesting + node/`Identifier` placement.

### 2.6 Deferred-policy posture: additive config; OTLP LIFTED from the ADR-0041 silent-ignore set *(self-answered; pinned at SPEC, D-OTLP-REJECT)*

The OTLP typed_config moves from "silently ignored" (`bootstrap.go:336`) to "parsed + enforced"; `transport_api_version` V2 + `google_grpc` + empty `cluster_name` are strict-rejected (the reused `CommonGrpcAccessLogConfig` arms); `formatters` is always strict-rejected (out of scope); `body`/`attributes`/`resource_attributes` are strict-rejected at 45.1 (deferred to 45.2) then accepted at 45.2 — an EXPLICIT per-sibling reject per `reference_strict_reject_sibling_typeurl_gap` (no silent drop of a to-be-supported field). The `AccessLog.filter` field stays silently ignored (a deferred sub-surface, §8).

### 2.7 Stat surface hypothesis: a small `access_logs.open_telemetry.*` counter set + incidental OTLP-cluster upstream stats *(self-answered; SPEC pins, D-OTLP-STATS)*

The OTLP cluster is dialed as a normal cluster, so it incidentally emits the standard `upstream_cx_*`/`upstream_rq_*` cluster stats (a unary-RPC connection). The sink-specific stats are the 2 process-global counters `access_logs.open_telemetry.{logs_written,logs_dropped}` (the ADR-0255 `access_logs.grpc_access_log.*` precedent — STATIC, NOT cluster-gated). Whether the names are fixed `access_logs.open_telemetry.*` or `stat_prefix`-derived is the D-OTLP-STATS pin (fixed ⇒ +2; `stat_prefix`-derived ⇒ +N).
