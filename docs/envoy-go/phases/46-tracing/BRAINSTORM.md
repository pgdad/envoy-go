**Status:** brainstorm complete (lifecycle-state 0 → 1). This document captures the design decisions reached during the brainstorm session for phase 46 (`tracing`), the **THIRD row of the Observability family** (the family that OPENED at phase 44 [gRPC ALS] and STAYS OPEN; rows 44 `grpc-access-log` and 45 `otlp-access-log` are `done`). Per ADR-0106 the family stays open across rows; phase 46 charters the next row with a fresh BRAINSTORM. Phase 46 delivers **HCM-native request tracing** — the `HttpConnectionManager.tracing` field (proto field 7, currently silent-ignored) driving a per-request span with a configured provider, full sampling/request-id fidelity, trace-context propagation, and a span exporter (OTLP gRPC first; Zipkin JSON second).

Phase 46 is the natural THIRD Observability-family row: it composes on substrates the family ALREADY built rather than inventing them — (i) the **phase-45 OTLP machinery** (the `go.opentelemetry.io/proto/otlp v1.0.0` module already promoted direct in go.mod, the unary-`Export` typed-client shape, the bounded-channel-+-writer-goroutine batching sink), and (ii) the **phase-18 gRPC client layer** (`internal/grpcclient` — the cluster-name→`*grpc.ClientConn` `Dialer` + the typed-wrapper precedents `AuthClient`/`OTLPLogsClient`, ADR-0158). Where phase 45 EXPORTED access-log `LogRecord`s over `LogsService.Export`, phase 46 EXPORTS tracing `Span`s over `TraceService.Export` — the SAME OTLP collector module, a sibling unary RPC. The genuinely NEW substrate is the **span lifecycle + the sampling/request-id decision engine + trace-context propagation**, which is HCM-native (it touches the request path itself, not an `accesslog.Sink`) and lands in a NEW `internal/tracing` package.

## 1. Mission and scope confirmation (46 — the parent + the 2 legs)

### 1.1 What phase 46 delivers as a self-contained whole (envelope: HCM-native tracing — provider engine + sampling + propagation + OTLP/Zipkin exporters)

Phase 46 delivers working `HttpConnectionManager.tracing` request tracing: when an HCM carries a `tracing` block with a recognized provider, envoy-go runs the sampling/request-id decision per request, generates an `x-request-id` (the `request_id_extension` UUID) when absent, extracts/continues an incoming trace context (`traceparent` for OTel / `b3` for Zipkin) or starts a fresh trace, builds a per-request `Span` (start at dispatch, end at the access-log emit seam), and EXPORTS sampled spans to the configured collector — over `TraceService.Export` for the OTel provider (46.1), over an HTTP/JSON POST for the Zipkin provider (46.2). Byte-identical when no `tracing` provider is configured (the no-tracing path is untouched — the full differential is the regression anchor).

### 1.2 What phase 46 does NOT deliver (forward to §8)

The deferred provider extensions: OpenTelemetry `http_service` (the HTTP trace transport — gRPC-only in 46.1), `resource_detectors`, the OTel `sampler` extension (sampling is HCM-side via the Percent knobs); the HCM `custom_tags` (literal/header/metadata/environment tag enrichment), `verbose` span logging, `max_path_tag_length`, `spawn_upstream_span` (a separate upstream span — single-span-per-request in the core unless a probe shows otherwise); the non-OTel/non-Zipkin providers (Datadog, Lightstep, SkyWalking, XRay, dynamic_ot — each a future row or strict-reject); `tracestate` rich propagation beyond pass-through; `grpc_service.google_grpc` (non-Envoy-gRPC). Each is a future leg/row or a documented strict-reject.

### 1.3 Phase-done as the THIRD Observability-family row landing (family STAYS OPEN)

Phase 46 is the THIRD row of the Observability family; the family stays OPEN (stats sinks + the tap filter remain future rows). The row registers `in-progress` at this brainstorm and flips `done` once BOTH legs land (per-leg ADR-0106 + `reference_roadmap_split_phase_row_done` — the row-44/45 precedent: a split phase's row flips `done` when ALL chartered legs land). ### 1.4 ADR-0045 split readiness — a pre-authorized by-exporter 2-leg split, with a 46.1 sub-split contingency

## 2. Design decisions

### 2.1 Family-row confirmation: the Observability family's THIRD row is tracing *(Q0 → phase 46 row registered)*

The Observability family stays open; the third row is tracing (over stats sinks, the tap filter). Rationale: it reuses the phase-45 OTLP module + the unary-Export sink pattern at the lowest incremental risk, it is canonical Envoy, and its structured-`Span`-proto differential follows the deterministic 45.x receiver model.

### 2.2 Envelope: HCM-native tracing with full sampling fidelity + OTLP then Zipkin *(Q1/Q2 → the accept set)*

Accept the HCM `tracing` block: `client_sampling` + `random_sampling` + `overall_sampling` (the full decision), `provider` (OTel in 46.1, Zipkin in 46.2). Accept the OTel `OpenTelemetryConfig.{grpc_service, service_name}`. Generate the `request_id_extension` UUID `x-request-id` with the byte-14 sampling-decision encode; propagate W3C `traceparent` (46.1) / B3 (46.2). Strict-reject the out-of-scope provider/HCM sub-fields (§2.6, §3). HTTP-only (the span is built from the HTTP request path).

### 2.3 Split axis: by-exporter, 46.1 (core+OTLP) → 46.2 (Zipkin+B3), with a 46.1a/46.1b contingency *(Q-split → ADR-0260 + ADR-0261, possibly ADR-0260a/0260b)*

By-exporter over flat (both exporters at once — too large) and over Zipkin-first (Zipkin's HTTP/JSON transport reuses less of the built machinery). The OTel and Zipkin exporters are different transports (gRPC unary vs HTTP/JSON POST) with different native propagation formats (`traceparent` vs `b3`) — a clean per-leg boundary. The 46.1a/46.1b sub-split is the ADR-0045 contingency for the large full-fidelity core (§1.4).

### 2.4 The sampling/request-id decision engine: full fidelity *(self-answered shape; pinned at SPEC, D-TRACE-SAMPLING / D-TRACE-REQUESTID)*

A per-request decision composing `client_sampling` (forced via `x-client-trace-id` presence), `random_sampling` (the % knob, evaluated against a deterministic-for-the-differential RNG seam), `overall_sampling` (the global cap), and the incoming `traceparent` sampled-bit, encoded into the `x-request-id` UUID byte-14 trace-decision nibble (the default `request_id_extension`). The EXACT precedence + the UUID byte semantics + the external-vs-internal request trust (whether a client-supplied `x-request-id` is preserved) are the §10 SPEC live-probes.

### 2.5 The span model + propagation: a per-request Span over the existing seam *(self-answered shape; pinned at SPEC, D-TRACE-SPAN / D-TRACE-PROPAGATION)*

A `Span` started at `dispatchRequest` (`connection.go:448`) and ended at the access-log emit seam (`accesslog_emit.go:19`/`:45`), carrying the trace-id (continued from an incoming `traceparent`, or freshly generated), the span-id, the parent-span-id (from the incoming context), the span name + kind + start/end times + the default attribute set (the OTel HTTP semantic conventions Envoy emits). `traceparent` is extracted on ingress + injected toward the upstream. The exact span name, kind (SERVER vs CLIENT), the default attribute roster, and the trace-id continuation-vs-fresh rule are the §10 SPEC live-probes.

### 2.6 Deferred-policy posture: additive config; the HCM `tracing` field LIFTED from the ADR-0041 silent-ignore set *(self-answered; pinned at SPEC, D-TRACE-REJECT)*

The HCM `tracing` block moves from "silently ignored" to "parsed + enforced". STRICT-REJECT (ADR-0080) the out-of-scope provider/HCM sub-fields: an unrecognized `provider.name`/`typed_config` (non-OTel in 46.1, non-OTel/non-Zipkin overall); OTel `http_service`/`resource_detectors`/`sampler`; HCM `custom_tags`/`verbose`/`max_path_tag_length`/`spawn_upstream_span`; non-V3 transport; `google_grpc`. The exact accept/reject partition is SPEC-pinned (D-TRACE-REJECT) — the envoy-go-strict mirror of the reference's own config validation.

### 2.7 Stat surface hypothesis: a tracing stat set under `http.<stat_prefix>.tracing.*` + incidental collector-cluster upstream stats *(self-answered; SPEC pins, D-TRACE-STATS)*

Envoy emits per-HCM tracing counters (e.g. `tracing.random_sampling`, `tracing.client_enabled`, `tracing.client_disabled`, `tracing.service_forced`, `tracing.not_traced`, `tracing.health_check`) under the HCM stat prefix. The collector cluster (OTLP gRPC / Zipkin HTTP) is dialed as a normal cluster, so it incidentally emits the standard `upstream_cx_*`/`upstream_rq_*`. The EXACT tracing stat names + scope + the `+N` surface delta are SPEC-pinned against `contrib-v1.37.2`. NOTE: any `stat_prefix`-keyed dynamic stat segment must pass `stats.IsValidName` before `NewCounterIfAbsent` (`reference_dynamic_stat_name_charset_guard`).
