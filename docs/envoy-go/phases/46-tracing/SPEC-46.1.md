## 1. Purpose / Mission

Deliver envoy-go's FIRST request-tracing subsystem: when an HCM carries a `tracing` block with a recognized OpenTelemetry provider, envoy-go runs the full-fidelity sampling/request-id decision per request, generates (or preserves-and-stamps) the `x-request-id` UUID with the trace-reason encoded into its byte-14 nibble, extracts an incoming W3C `traceparent` (continuing its trace-id) or starts a fresh trace, builds a per-request **SERVER** span (start at dispatch, end at the access-log emit seam), injects the new span context toward the upstream, and EXPORTS sampled spans to the configured collector over the UNARY `TraceService.Export`. This is the project's FIRST consumer of the `go.opentelemetry.io/proto/otlp` **trace** signal (the `trace/v1` + `collector/trace/v1` packages, siblings of the `logs/v1` packages phase 45 consumed — already direct in `go.mod`, ZERO new modules) and the FIRST genuinely-new request-path subsystem in a long stretch (ONE new Go package `internal/tracing`). It composes on THREE already-built substrates — the phase-18 `grpcclient` layer, the phase-44.2/45.1 batching-sink machinery, and the HCM request-lifecycle seams — adding ONE new package and ZERO new go.mod modules. Byte-identical when no `tracing` provider is configured (every non-tracing path is untouched; the full differential is the regression anchor). It ANCHORS ADR-0260; the row-46 Observability-family row flips `done` only at the FINAL leg (46.2) IMPL (ADR-0106); the Observability family STAYS OPEN.

### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-27, contrib-v1.37.2 — an H1 downstream → a real HTTP backend, with an HCM `tracing` block [OpenTelemetry provider, `random_sampling=100%`, `service_name` set] exporting to a driver-owned h2c OTLP `TraceService` receiver, all on a shared bridge per `reference_docker_probe_bridge_network`; **decode-ran proof: `tracing.opentelemetry.spans_sent: 6` + 6 captured `ResourceSpans` in the receiver, the SERVER span name `ingress` / kind `SPAN_KIND_SERVER` confirmed**) drove these amendments. Several CORRECT brainstorm hypotheses; the engine matches the proto shapes but the span/stat ROSTERS differ from the brainstorm guesses.

- **AMEND-TRACE-SPAN-SHAPE (the SERVER span is named the constant `"ingress"`, kind `SPAN_KIND_SERVER`; the instrumentation scope IS populated — `name="envoy"`, `version=<build>` — UNLIKE the OTLP-logs empty scope; a CONCRETE 16-attribute roster, NOT the brainstorm's open "OTel HTTP semantic conventions" guess).** Live finding (D-TRACE-SPAN): a non-continued request yields exactly ONE span — `name:"ingress"`, `kind:SPAN_KIND_SERVER` (=2), `start_time_unix_nano`/`end_time_unix_nano` both populated, `parent_span_id` EMPTY (root). Its `attributes` are 16 fixed keys: `node_id`, `zone`, `guid:x-request-id`, `http.url`, `http.method`, `downstream_cluster`, `user_agent`, `http.protocol`, `peer.address`, `request_size`, `response_size`, `component`(=`proxy`), `upstream_cluster`, `upstream_cluster.name`, `http.status_code`, `response_flags` (+ `guid:x-client-trace-id` when that header is present). The OTLP `ScopeSpans.scope` is `{name:"envoy", version:<build-hash>}` (NOT absent like the 45.1 logs `ScopeLogs.scope`). The `ResourceSpans.resource.attributes` are `service.name`(←`OpenTelemetryConfig.service_name`) + `telemetry.sdk.{version,language=cpp,name=envoy}` (the SDK trio is implementation-specific — envoy-go is NOT cpp; only `service.name` is cross-side assertable). This REPLACES the brainstorm §2.5 open guess ("span name — cluster name? operation?") with the pinned constant `"ingress"` + the concrete roster.
- **AMEND-TRACE-SPANEND-SEAM (the span END corresponds to stream-complete = the `accesslog_emit.go` seam; the §2.5 placement is empirically grounded — the folded advisory).** Live finding (D-TRACE-SPAN end-time sub-prong): every captured span had `end_time_unix_nano > start_time_unix_nano` spanning the full request (start at request dispatch, end at downstream-response-complete). The reference finishes the active SERVER span at stream completion — the SAME point the access log fires. 46.1 ends the span at the `accesslog_emit.go:19`(H1)/`:45`(H2) seam (which already carries `statusCode`/`bytesSent`/`start time.Time`/`respHeaders`), NOT an earlier upstream-response-complete point.
- **AMEND-TRACE-REQUESTID-NIBBLE (the trace reason is encoded at x-request-id STRING index 14 [the UUID version nibble]; NoTrace=`4` / Sampled=`9` / Client[x-client-trace-id]=`b`; an incoming x-request-id is PRESERVED with ONLY index-14 overwritten; a CONTINUED trace keeps the NoTrace `4` nibble).** Live finding (D-TRACE-REQUESTID): the generated `x-request-id` is UUIDv4-shaped; the trace-decision is the character at string index 14 (first hex of the 3rd hyphen group, the version field): `4`=NoTrace (random=0, no force), `9`=Sampled (random decision), `b`=Client (`x-client-trace-id` force). When the request ARRIVES with an `x-request-id`, the reference PRESERVES it verbatim EXCEPT it overwrites index 14 with the local reason (probed: `aaaaaaaa-bbbb-cccc-…` → `aaaaaaaa-bbbb-9ccc-…`). For a CONTINUED trace (incoming `traceparent`), the local reason stays `4` — the nibble reflects only LOCAL random/force decisions, not propagation. The `x-request-id` is GENERATED + injected upstream REGARDLESS of the sampling decision (a not-sampled request still gets a fresh `x-request-id` and an upstream `traceparent` with flags `00`).
- **AMEND-TRACE-SAMPLING-PRECEDENCE (continued traces bypass local caps; `overall_sampling` caps ONLY locally-decided samples; the stat-increment roster is `client_enabled`/`random_sampling`/`not_traceable`, NOT the brainstorm's `client_disabled`/`not_traced`).** Live finding (D-TRACE-SAMPLING): an incoming `traceparent` is authoritative — its sampled-bit is continued and is NOT subject to `random_sampling` or `overall_sampling` (probed: `random_sampling=0`+incoming-sampled → still sampled; `overall_sampling=0`+incoming-sampled → still sampled), and is classified `not_traceable` locally. For a request WITHOUT incoming context: `x-client-trace-id` forces sampling (gated by `client_sampling` — `client_sampling=0` suppresses the force, dropping `client_enabled` to 0), else `random_sampling` decides; THEN `overall_sampling` is a global cap over the locally-decided sample (`overall_sampling=0` suppressed BOTH random AND client-force). The HCM-scoped counters are `client_enabled`/`health_check`/`not_traceable`/`random_sampling`/`service_forced` (5) — the brainstorm's `client_disabled`/`not_traced` DO NOT EXIST.
- **AMEND-TRACE-STATS (5 HCM-scoped `http.<stat_prefix>.tracing.*` + 3 tracer-scoped `tracing.opentelemetry.*`; the surface delta is +N over a candidate 5–8, IMPL-pinned).** Live finding (D-TRACE-STATS): HCM-scoped `http.ingress_http.tracing.{client_enabled,health_check,not_traceable,random_sampling,service_forced}` (5) + tracer-scoped `tracing.opentelemetry.{spans_sent,spans_dropped,timer_flushed}` (3). `spans_sent` == sampled-span count (decode-ran proof). The HCM-scoped 5 are the firm envoy-go surface (the decision-engine outcomes); the exporter counters are an envoy-go naming decision (the 45.1 `logs_written`/`logs_dropped` analog; `timer_flushed` is an Envoy-flush-timer artifact, likely dropped). Surface **1191 → 1191+N** (N≈5–7; the EXACT figure is an IMPL registration-test pin, §7). The HCM `stat_prefix` is a DYNAMIC segment — it MUST pass `stats.IsValidName` before `NewCounterIfAbsent` (`reference_dynamic_stat_name_charset_guard`).
- **AMEND-TRACE-NO-BOOT-REJECT-ON-MISSING-CLUSTER (the reference does NOT boot-reject a missing collector cluster; envoy-go's Dialer cluster-exists gate makes that a documented envoy-go-strict boot-reject departure).** Live finding (D-TRACE-REJECT): with `grpc_service.envoy_grpc.cluster_name` pointing at a NONEXISTENT cluster the reference BOOTS (export silently fails). envoy-go's `grpcclient.Dialer.DialContext` requires the cluster to EXIST + be H2; a `NewOTLPTracesClient` failure is a `log.Fatalf` boot failure (the 45.1 `main.go` precedent) — a stricter, fail-fast departure (§2, §8.1 boot-reject prong). ### 3.3 The `internal/tracing` package — the engine (sampling/request-id decision + span model + propagation + the `Exporter` seam + the OTLP exporter impl)

ONE new package. Its pieces (the PLAN decides file decomposition):

- **The sampling/request-id decision (`decision.go`):** `Decide(h http.Header, cfg *TracingConfig, rng RandSource) Decision` returning `{Sample bool, Reason TraceReason, TraceID [16]byte, ParentSpanID [8]byte, SpanID [8]byte, Continued bool, RequestID string}`. The full-fidelity precedence (§11 D-TRACE-SAMPLING):
  1. an incoming `traceparent` ⇒ CONTINUE (parse the trace-id + parent-id + sampled-bit; `Sample = sampled-bit`; NOT subject to local caps; `Reason` stays NoTrace; classify `not_traceable`).
  2. else `x-client-trace-id` present ⇒ FORCE candidate (gated by `client_sampling`; `Reason=Client`; classify `client_enabled`).
  3. else `random_sampling` roll ⇒ candidate (`Reason=Sampled` when it fires; classify `random_sampling`).
  4. THEN `overall_sampling` caps the locally-decided candidate (steps 2–3 only; NOT step 1).
  The `x-request-id` is GENERATED when absent (a UUIDv4 with byte-14 set to the `Reason` nibble: NoTrace=`4`/Sampled=`9`/Client=`b`) or PRESERVED-and-stamped when present (overwrite ONLY string index 14). The `RandSource` is an injectable seam so the differential can force a deterministic decision (`random_sampling=100%`).
- **The span model (`span.go`):** `Span{ TraceID, SpanID, ParentSpanID, Name="ingress", Kind=SERVER, Start, End time.Time, Attrs []KV }` — built from the decision + the request-lifecycle inputs. The 16-attribute built-in roster (§11 D-TRACE-SPAN; the deterministic subset is the cross-side-assertable target).
- **Propagation (`propagation.go`):** `ExtractTraceparent(h) (ctx, ok)` (W3C `00-<32hex>-<16hex>-<2hex>`) + `InjectTraceparent(h, traceID, spanID, sampled)` + `tracestate` pass-through. `reference_wire_format_both_sides_see_same_bytes` — adopt the reference framing verbatim.
- **The exporter seam (`exporter.go`):** `type Exporter interface { Export(*Span); Close() error }`; the OTLP impl `OTLPExporter` wraps a sink-facing `otlpTracesClient interface { Export(ctx, *coltracepb.ExportTraceServiceRequest) (...); Close() error }` (the `*grpcclient.OTLPTracesClient` satisfies it structurally — no import cycle, the 45.1 `otlpClient` seam precedent). The exporter mirrors the 44.2/45.1 bounded-channel + writer-goroutine + size/interval/close BUFFER → builds ONE `ExportTraceServiceRequest{ ResourceSpans:[ one ResourceSpans{ Resource{service.name+sdk}, ScopeSpans:[{ Scope{name:"envoy",version:<envoy-go build>}, Spans:[batch] }] } ] }` per flush, calls `client.Export`, `spans_sent.Add(len(batch))` on success, retry-once-then-drop on error (`spans_dropped`). The 46.2 Zipkin exporter is a SECOND `Exporter` impl (a different transport) behind the same seam.

### 3.5 HCM wiring (`internal/filter/hcm`) — the span lifecycle on the existing seams

- **Decision + request-id + span-start at dispatch:** at `connection.go:448` (`startTime := time.Now()` in `dispatchRequest`), when the HCM has a `TracingConfig`, run `tracing.Decide(reqHeaders, cfg, rng)`, stamp/generate `x-request-id` onto the request headers, `InjectTraceparent` toward the upstream, and open the span (carrying `startTime`). This REVISES the `router.go:763` no-`x-request-id`-injection invariant — but ONLY under a configured provider (no provider ⇒ the request path stays byte-identical, the regression anchor).
- **Span-end at the access-log seam:** at `accesslog_emit.go:19`(H1)/`:45`(H2) (`emitAccessLog`/`emitAccessLogH2`, which already receive `statusCode`/`bytesSent`/picked `cluster.Endpoint`/`start time.Time`/`respHeaders`), finalize the span (end-time, status_code, sizes, response_flags, upstream_cluster) and hand it to the `Exporter` IF `decision.Sample` (AMEND-TRACE-SPANEND-SEAM). The span and the access-log Record share these inputs — tracing reuses the seam, not a parallel one.
- **The HCM-scoped `tracing.*` counters** increment at the decision point (per the §11 outcome classes).

### 8.1 `0086-tracing-otlp` (cross-side EXACT — poll-to-converge then aggregated per-span assertion)
