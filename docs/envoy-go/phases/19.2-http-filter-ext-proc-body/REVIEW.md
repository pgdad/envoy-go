## 9. Lessons learned

**The encode-side body-buffering primitive lives at the CHAIN level, not the per-encoderCB level — IMPL-time architectural finding contra SPEC §3.1 hypothesis.** The SPEC §3.1 anticipated per-encoderCB layout (`encodeBuf []byte` field on each `*encoderCB`); the IMPL settled chain-level instead per three concrete reasons documented in ADR-0175 §Decision (ii): decode-side precedent symmetry (decode lives at chain-level via `c.decodeBuf`); chain-iteration model alignment (RunEncodeData's single-cursor + single-`data` local does NOT carry an owning-filter-index context); cap-check natural composition (the existing `c.encodeBufLen` cap is chain-scoped). **Lesson:** when introducing a primitive that mirrors a decode-side analog, FIRST verify whether the decode-side analog lives at the chain level or the per-callback level; carry forward the same layer choice unless an explicit asymmetry is documented at SPEC time. The IMPL-time settle pattern (architectural-finding + ADR §Decision-body documentation; no new ADR consumed) is the canonical ADR-0044-respecting closure.

**Decode-side body-mutation-delivery has a framework-level gap that surfaces only at the chain-to-cluster handoff.** Task 7's IMPL surfaced that the framework's `DecodeData(buf, end_stream=true)` cursor does not propagate the post-mutation buffer to the upstream cluster. The filter-level mutation application is correct (Task 6 unit tests + Task 8 race tests confirm); the gap is at the chain-to-cluster handoff. **Lesson:** filter-level unit tests + race tests are NECESSARY but NOT SUFFICIENT for verifying end-to-end body-mutation delivery; fixture-harness scrapes against reference Envoy are the load-bearing closure surface. Future phases that touch body-mutation paths should include a fixture-harness scrape ahead of unit-test completion to surface chain-to-cluster handoff gaps.

**Reference Envoy v1.37.2 has body-stage body_mutation quirks that the planner-time hypothesis cannot anticipate.** Task 9 scenarios (b) and (d) hypothesized straightforward body replacement/clear via `body_mutation{body|clear_body}` at the response_body stage; reference Envoy returned 500 with empty body regardless of backend shape. **Lesson:** reference-proxy quirks at body-stage interactions are HIGHLY likely to surface at fixture-harness scrape time; the SPEC + PLAN scenario hypotheses should be authored with explicit "OBSERVABILITY-only fallback" scope-reduction as a pre-anticipated empirical-pin AMENDMENT class. The 19.2 SPEC's §11 "No new pins anticipated" stance was load-bearing-correct (no NEW ADR consumed) but the empirical-AMENDMENT pattern is the right closure pattern for these quirks.

**The "async-resume signaling discipline at filter completion paths" bug class continues to surface.** Task 7 rework `bb8219c` C-1 skip-flag bug is a fresh instance of the 19.1 Task 13 scenario-2 "signalResume(s) after SendLocalReply" lesson, this time on the per-direction skip-flag honor surface for CONTINUE_AND_REPLACE. **Lesson:** any per-direction skip-flag + dispatch-decision interaction is a CHECKLIST ITEM for new filter completion paths. Future filter-completion code reviews should include: "for each per-direction permutation (decode/encode × header/body × skip/no-skip), confirm the dispatch decision honors the skip-flag on the correct arm".

**Single-Task BEHAVIOR_CONTRACT bundle is cleaner than split-across-Tasks for small envelopes.** The 19.2 D9 single-Task closing bundle at Task 10 is more grep-coherent than 19.1's 8-edit bundle split across Tasks 13+14. **Lesson:** prefer single-Task BEHAVIOR_CONTRACT bundles when the envelope permits (< ~10 edits + < ~300 LoC net); split-across-Tasks remains valid when an early edit depends on a fixture scrape that lands first (the 19.1 split rationale).
