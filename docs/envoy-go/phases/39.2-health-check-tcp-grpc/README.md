**The architecture (SPEC §3).** A small `prober` interface — `probe(addr) (ok, networkFailure bool)` — with three implementations: `httpProber` (the 39.1 `probeHTTP` body unchanged), `tcpProber` (a `net.Dialer{Timeout}.Dial("tcp", addr)` + immediate close — connect-only), `grpcProber` (a `grpc.health.v1.Health/Check` unary call: dial over H2 insecure, `Check(ctx, &HealthCheckRequest{Service: serviceName})`, classify `err != nil` ⇒ network_failure else `Status == SERVING` ⇒ ok). `parseHealthChecks` returns a kind-tagged `[]checkerSpec{ envelope, prober }`; `healthChecker` holds the envelope + a `prober` instead of `cfg httpHealthCheckCfg`; `probeOnce`/`applyResult`/`run`/`StartHealthChecks`/`Drain` + the six-LB health view are UNCHANGED. The only new wiring is the gRPC cluster-must-be-H2 reject (against the cluster's parsed protocol at `buildCluster`).

**The differential proof (poll-to-convergence; the 39.1 `0066` lineage).** TWO fixtures (39.2): `0067-health-check-tcp` — a cross-side connect-only TCP HC over {2 LIVE HTTP backends (a bare TCP connect to their port succeeds — `HTTPEcho` REUSED, **NO new BackendKind**), 1 DEAD unbound port}, 66% healthy; and `0068-health-check-grpc` — a cross-side gRPC HC over an H2 cluster {2 LIVE gRPC SERVING responders (a **+1 BackendKind** `GRPCHealthResponder` — an h2c server answering `grpc.health.v1.Health/Check` ⇒ SERVING AND returning 200 to plain-H2 data-plane requests), 1 DEAD unbound port}. Both follow the `0066` protocol: poll `membership_healthy == 2` → a warmup-until-K-consecutive-200s gate (`reference_health_check_propagation_warmup`) → a measured-phase 100%-live assertion + per-request counter DELTAs → cross-side `health_check.*`/`membership_healthy` parity. Gate on convergence + warmup, NOT raw `attempt` deltas (no-traffic deactivation — TG7). Each leg proven live via `-count=1` deliberate-breaks (the prober ignores its result ⇒ convergence times out; `Pick` ignores health ⇒ warmup never stabilizes).
