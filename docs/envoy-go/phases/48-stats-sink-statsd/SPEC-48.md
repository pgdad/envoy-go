## 1. Purpose / Mission

Deliver envoy-go's SECOND stats-export sink and the FIRST consumer of the bootstrap `stats_sinks[]` `StatsdSink` TypeURL: when the bootstrap carries a `statsd` `stats_sinks[]` entry with a UDP `address`, envoy-go dials that UDP address once (`net.DialUDP` — the FIRST `net.UDPConn` in the tree) and every `stats_flush_interval` (default 5s) snapshots the frozen process-global `stats.Registry` (via the SAME `snapshot()` the metrics_service sink uses — `mapping.go:22`) and writes one statsd line per metric as a UDP datagram to the configured address: `<prefix>.<name>:<value>|c` for each COUNTER family (the value is the **per-flush delta** — D-SD-DELTA, the canonical statsd increment), `<prefix>.<name>:<value>|g` for each GAUGE family (the value is the **absolute** current value), `<name>` = the full dotted internal name with tags INLINED and ZERO labels (the proto "does not support tagged metrics"), `<prefix>` = `StatsdSink.prefix` joined `prefix + "." + name` (default `envoy`). This composes ENTIRELY on the phase-47 substrate (the `Flusher` registry-snapshot loop, the `Sink` interface, the `snapshot()` cumulative-absolute mapping, the `deltaState` per-flush-delta transform, the `stats_sinks[]`/`stats_flush_interval` parse, the `main.go` post-Freeze flusher build) — it adds NO new framework piece: ONE new `Sink` impl (`internal/statssink/statsd.go`), ONE new bootstrap parse arm, ONE new config struct, ONE UDP datagram seam. ZERO new Go packages, ZERO new go.mod modules (the statsd line protocol is hand-rolled `strconv`/`net` — no client lib; the `StatsdSink` proto resolves at the ALREADY-blank-imported `config/metrics/v3` package). ### 1.1 Empirical-finding-driven scope (amendment block per ADR-0044)

The §11 live probe (2026-06-30, contrib-v1.37.2 — an H1 downstream :10000 `stat_prefix=ingress_http` → an `hashicorp/http-echo` backend, K=7 requests, with a bootstrap `statsd` `stats_sinks[]` entry [UDP `address` → a driver-owned Go UDP receiver at a static bridge IP `172.31.99.10:8125`, `prefix: probepfx`] + `stats_flush_interval=1s`, all on a shared Docker bridge per `reference_docker_probe_bridge_network`; **decode-ran proof: 657 UDP datagrams received over the run, `probepfx.cluster.backend.upstream_rq_total` emitting `7,0,0,0` across four flushes [SUM == 7 == K, last-seen 0]**) CONFIRMED the brainstorm's core hypotheses (full dotted name, no labels, prefix join, +0 self-stats) and RESOLVED the LOAD-BEARING D-SD-DELTA question (DELTA, not absolute) plus the line/reject roster. The findings that RESHAPE the design vs the brainstorm's "self-answered" defaults:

- **AMEND-SD-DELTA-CONFIRMED (the LOAD-BEARING finding — counter `|c` is a per-flush DELTA-since-last-flush, NOT absolute ⇒ the `StatsdSink` UNCONDITIONALLY owns a sink-private `deltaState`, and `0092` asserts the delta-SUM with a post-convergence stability barrier, NOT `0089`'s absolute `value==K`).** Live finding (D-SD-DELTA): the COUNTER `cluster.backend.upstream_rq_total` (and `http.ingress_http.downstream_rq_total`, `downstream_rq_2xx`, etc.) emitted `7|c` on the single flush following the K=7 requests and `0|c` on every other flush (3 zeros before/after) — SUM of deltas == 7 == K, **last-seen == 0**. This is the canonical statsd increment semantics. **Consequence:** UNLIKE the metrics_service sink (where `report_counters_as_deltas` is a CONFIG knob, default cumulative-absolute), the statsd sink's `|c` is ALWAYS a delta — it is intrinsic to the statsd line protocol, with no config knob. So the `StatsdSink` ALWAYS builds a sink-private `deltaState` (reusing the landed `internal/statssink/delta.go` `newDeltaState()`/`apply()` — counters→delta, gauges→absolute, no shared-slice mutation, the same pattern 47.2a landed) and the `0092` differential CANNOT use `0089`'s absolute `value==K` last-seen (it would read 0); it asserts the delta-SUM across all received flushes == K AND that the SUM is STILL K after ≥2 further (zero-delta) flushes (the post-convergence stability barrier — `reference_delta_sink_differential_stability_barrier`; a single first-reach-K could not distinguish delta from absolute). GAUGES (`|g`) are absolute (e.g. `membership_healthy:1|g`, `max_host_weight:1|g`) with NO sign prefix.
- **AMEND-SD-LINE-CONFIRMED (one statsd line per UDP datagram — NOT newline-batched packing; integer values; no `@rate` sampling suffix; no signed values).** Live finding (D-SD-LINE): all 657 datagrams carried EXACTLY ONE statsd line each (0 multi-line datagrams; max 77 bytes), framed `<prefix>.<name>:<int>|<type>`. No `@rate` sampling tail, no `+`/`-` signed-delta-gauge syntax. The reference ALSO emits `|ms` timer lines (e.g. `upstream_rq_time:0|ms`) for histograms — envoy-go has ZERO histograms (ADR-0060), so envoy-go's emitter produces ONLY `|c` and `|g` lines (the `|ms` arm is unreachable). **Consequence:** the `StatsdSink` writes ONE datagram per metric family (a simple per-family `WriteToUDP`/`Write` loop; NOT a batched-packet packer — the one-line-per-datagram form is the reference's wire shape and the simplest correct impl; a newline-batched packing optimization is an UNCONSUMED IMPL micro-decision, §2/§8). The value is the integer delta/absolute (`strconv.FormatInt`/`FormatUint`).
- **AMEND-SD-NAME-CONFIRMED (the full dotted internal name with tags INLINED, ZERO labels; the prefix join is `prefix + "." + name`; the default prefix is `envoy`).** Live finding (D-SD-NAME): names are the full dotted internal form with tag VALUES inlined (`cluster.backend.external.upstream_rq_200`, `http.ingress_http.downstream_rq_2xx`), prefixed `probepfx.<name>`. The no-prefix variant emitted `envoy.<name>` — **default prefix CONFIRMED `envoy`**. This is the SAME `/stats`-internal-name model the metrics_service sink and the Prometheus exporter use — cross-side name-compatible (the redis/Prometheus `StatsAsserter` precedent). ZERO tag-as-label machinery (the proto does not support tagged metrics; the 47.2b `labelMapper` is metrics_service-only).
- **AMEND-SD-REJECT (the reference is PERMISSIVE on `tcp_cluster_name` [accepts statsd-over-TCP] and IGNORES the `socket_address.protocol` field [TCP-protocol still emits UDP datagrams], but HARD-REJECTS a missing `statsd_specifier` oneof and a non-IP [hostname] address ⇒ envoy-go is REFERENCE-PARITY on the missing-specifier reject and envoy-go-STRICT on `tcp_cluster_name`; the `protocol` field is accepted-and-ignored [dial UDP] for parity).** Live finding (D-SD-REJECT, 4 config variants): a `StatsdSink` with NEITHER `address` nor `tcp_cluster_name` → the reference REJECTS at config-load (`Proto constraint validation failed (field: "statsd_specifier", reason: is required)`, exit 1 — a PGV oneof-required constraint); a hostname `address` (`receiver`) → REJECTS (`malformed IP address: receiver`, exit 1 — the statsd UDP sink does NOT DNS-resolve, it parses a literal IP); a standalone `tcp_cluster_name` (with the named cluster present) → BOOTS (permissive — statsd-over-TCP); a `socket_address` with `protocol: TCP` → BOOTS and STILL emits UDP datagrams (the reference IGNORES `protocol` for the statsd sink — always UDP). ⇒ envoy-go REFERENCE-PARITY on the missing-`statsd_specifier` reject; envoy-go-STRICT (ADR-0080 anti-silent-divergence) on `tcp_cluster_name` (UDP-only this row — honoring it as UDP would silently mis-transport; §2); the `protocol` field is accepted-and-ignored (envoy-go dials UDP regardless — rejecting `protocol:TCP` would reject the proto-DEFAULT `TCP`(0) / common omit case, so parity is the least-surprise posture, §6).
- **AMEND-SD-NO-SELF-STATS-NO-CLUSTER (ZERO statsd-sink self-stats AND no sink cluster — surface delta +0; a UDP write is connectionless, so there is no incidental upstream-cluster stat either, UNLIKE the metrics_service gRPC cluster).** Live finding (D-SD-STATS): `curl /stats | grep -iE 'statsd|stat_sink|stats.sink'` → no matches; the reference registers no statsd-scoped self-stat. And because the UDP sink dials no cluster, there is no `upstream_cx_*`/`upstream_rq_*` family for it (contrast the metrics_service sink's long-lived gRPC cluster). Surface delta **+0** (1200 → 1200; non-H2 1196 → 1196).

Additional confirmed pins (no amendment): default `stats_flush_interval` 5s (the phase-47 pin, unchanged); the StatsdSink proto resolves at the pinned `go-control-plane/envoy v1.32.4` `config/metrics/v3` package (already blank-imported in `bootstrap.go`); `address`(1)/`tcp_cluster_name`(2)/`prefix`(3) field tags verified §11.

### 3.3 The `StatsdSink` (`internal/statssink/statsd.go`) — a `Sink` over a `*net.UDPConn` + the statsd-line mapping

ONE new file in the EXISTING `internal/statssink` package (a sibling to `sink.go`'s `MetricsServiceSink`). It satisfies the EXISTING `Sink` interface (`sink.go:18` — `Submit(batch []*dto.MetricFamily)` / `Close() error`):

- **Construction:** `NewStatsdSink(udpAddr string, prefix string) (*StatsdSink, error)` — `net.ResolveUDPAddr("udp", udpAddr)` + `net.DialUDP("udp", nil, raddr)`; stores the `*net.UDPConn`, the `prefix`, and a sink-private `deltaState` (`newDeltaState()` — AMEND-SD-DELTA-CONFIRMED, ALWAYS, no knob). A dial error is returned (→ `main.go` `log.Fatalf`, the metrics_service-client-error precedent).
- **`Submit(batch []*dto.MetricFamily)`:** apply the sink-private `deltaState.apply(batch)` (counters → per-flush delta, gauges → absolute, NO shared-slice mutation — the landed `delta.go` contract); then for each family, format ONE statsd line and write ONE UDP datagram:
  - COUNTER family `f` → `<prefix>.<f.Name>:<int delta>|c` (the value is the delta from `apply`; `strconv.FormatUint`/`FormatInt` of the integer — the metric carries `float64(delta)` but it is an exact integer, §11).
  - GAUGE family `f` → `<prefix>.<f.Name>:<int abs>|g` (absolute; gauges may be negative — `int64`; no sign-prefix delta-gauge syntax, AMEND-SD-LINE-CONFIRMED).
  - the prefix join is `prefix + "." + name` (AMEND-SD-NAME-CONFIRMED); one `conn.Write(line)` per family (one datagram per line — AMEND-SD-LINE-CONFIRMED).
  - a `Write` error is LOGGED-and-DROPPED (UDP is lossy by design; the rate-limited drop-log idiom from `sink.go`; NOT counted — +0 self-stats, AMEND-SD-NO-SELF-STATS).
- **`Close() error`:** close the `*net.UDPConn`, idempotent via `sync.Once` (the `sink.go` `closeOnce` precedent).
- **Writer shape (D-SD-LIFECYCLE — a PLAN pin):** the `Flusher` calls `Submit` serially from its single goroutine (one flush at a time; the sink contract forbids `Submit` after `Close`), and a UDP `Write` is non-blocking fire-and-forget — so a SYNCHRONOUS per-flush write loop (no bounded channel, no writer goroutine) is the simplest correct shape and the RECOMMENDED default (contrast the metrics_service sink's bounded-channel + writer-goroutine, which exists to absorb a slow/blocking gRPC stream — a UDP datagram never blocks on a peer). The PLAN MAY retain a writer-goroutine for `Submit`/`Close` symmetry, but the synchronous form is preferred (less machinery, no background mutator ⇒ the full-package `-race` concern is lighter — `reference_full_suite_race_after_background_mutator`).

### 3.4 The exported statsd-line shape (§11 D-SD-LINE/D-SD-NAME/D-SD-DELTA)

NO labels (tags inlined into the name). The cross-side-assertable target is the deterministic COUNTER delta-SUM over a name-subset (§8 / D-SD-SUBJECT).

## 8. Differential fixture taxonomy (+1: `0092` cross-side delta-SUM with a post-convergence stability barrier)

### 8.1 `0092-stats-sink-statsd` (cross-side — delta-SUM == K, then a flush-count stability barrier)

An **H1** downstream listener (`stat_prefix` fixed) → a route to a fixed-body backend, with a bootstrap `statsd` `stats_sinks[]` entry (UDP `address` → a driver-owned UDP receiver, **`stats_flush_interval` short** e.g. 200ms–500ms for fast deterministic convergence) on BOTH subject (in-process envoy-go) and reference (`contrib-v1.37.2`). Each side writes statsd-line datagrams to its OWN driver-owned UDP receiver (TWO per-side receivers + a hard `Close()` teardown — `reference_periodic_sink_differential_two_receivers`; the periodic flush streams datagrams for the whole test, so a single shared receiver would cross-contaminate and `GracefulStop` does not apply to a connectionless UDP listener). SLEEPLESS where possible: fire K (=7) deterministic requests, then poll-the-receiver until the accumulated delta-SUM for the subset reaches K on EACH side.

- **Assertions (cross-side, on the deterministic COUNTER name-subset — the delta-SUM + stability barrier, AMEND-SD-DELTA-CONFIRMED):** for the subset `{cluster.<backend>.upstream_rq_total, http.<stat_prefix>.downstream_rq_total, http.<stat_prefix>.downstream_rq_2xx}` (all COUNTER, all reaching cumulative K on both sides): the receiver accumulates the per-line `|c` deltas per name; assert **SUM of deltas == K** on each side AND that the SUM is STILL K after ≥2 FURTHER (zero-delta) flushes have arrived (the post-convergence stability barrier — `reference_delta_sink_differential_stability_barrier`; this distinguishes the delta semantics from absolute, which break (a) of the differential must demonstrate). The prefix join (`<prefix>.<name>`) and the `|c`/`|g` suffix are asserted by construction (the receiver keys on `<prefix>.<name>`). A GAUGE subset assertion (e.g. `cluster.<backend>.membership_healthy == 1|g` absolute on both sides) MAY be added (a cheap absolute-gauge cross-side check).
- **UNasserted:** the WHOLE line set / family count (the surfaces differ cross-side — the reference emits `|ms` histograms + many gauges envoy-go lacks); non-deterministic gauges (`server.uptime`, `*_active`, connection churn); the exact datagram/flush framing + per-flush line count (`reference_streaming_sink_differential_framing` — assert the aggregated delta-SUM payload, not framing); the `|ms` timer lines (envoy-go emits none).
- **Deliberate breaks (`reference_differential_break_protocol_count1` — `-count=1` on EVERY break; `reference_differential_run_selector` — `-run 'TestDifferential/0092'` NEVER bare):** (a) emit ABSOLUTE counter values instead of deltas (the stability barrier must FAIL — the SUM would over-count past K as each flush re-adds the cumulative absolute) — this proves the delta assertion is live; (b) a wrong prefix join / a `|g` for a counter (the subset lookup misses) — proves the name/type assertion is live; (c) drop the stability barrier and verify it would have masked break (a). Plus the 20/20 flake-stability run and the FULL-package `-race` on `internal/statssink` (the synchronous sink adds no background mutator, but the `Flusher` ticker remains one — `reference_full_suite_race_after_background_mutator`).
- **Receiver reachability (D-SD-RECEIVER-WIRING):** the in-process UDP receiver must be reachable from BOTH the subject (host) AND the reference (Docker container) — a shared bridge + a STATIC receiver IP (the §11 precedent — the statsd UDP `address` requires a literal IP, the reference does NOT DNS-resolve it; `reference_docker_probe_bridge_network`). The receiver binds a UDP port and accumulates per-name `|c` deltas + `|g` absolutes (a poll/assert surface mirroring `test/helpers/metricsservice`).
