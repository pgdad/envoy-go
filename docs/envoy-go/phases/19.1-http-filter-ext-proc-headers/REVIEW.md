## 12. Lessons learned

**Fixture-harness integration surfaces real production-correctness bugs.** The Task 13 fixture 0022 integration exposed three IMPL-time production bugs (scenario-2 delivery + runtime header-mutation wiring gap + HTTP-mode reachability) that the per-task unit tests + race tests had NOT caught. **Lesson:** the differential-fixture phase-closing discipline is non-vacuous — it stress-tests the integration surface against reference Envoy v1.37.2 in ways that synthetic unit tests cannot. The Task 13 4-commit rework stack (`0a117f1` + `28dfba1` + `b8b28fe` + `4baab4d`) is the precedent for how IMPL-time-surfaced production bugs get root-cause-fixed rather than papered-over with verdict-class relaxations.

**`signalResume(s)` after `SendLocalReply` is a project-wide async-resume discipline.** The scenario-2 bug was a regression of the SAME pattern documented at 4 independent call sites (ext_authz deny-path + ext_authz error-posture + fault.go combined fault + chain_test.go `timerSendLocalReplyFilter`). **Lesson:** when implementing a new async-resume call site in a filter, search for "SendLocalReply" + "ContinueDecoding" patterns project-wide and confirm the resume-signal discipline. Future code-review checklist item: any new `SendLocalReply` invocation from a goroutine OTHER than the dispatch goroutine MUST be paired with a `ContinueDecoding`/`signalResume` invocation.

**`protojson.UnmarshalOptions{DiscardUnknown:true}` is forward-compat-tolerance for both production AND test surfaces.** The HTTP-mode reference-side reachability gap (Open Follow-up #3) was the test driver's HTTP processor handler missing the same `DiscardUnknown:true` option that the production codec already used. **Lesson:** test-helper code that interoperates with reference Envoy MUST mirror the production codec's forward-compat-tolerance options. Reference Envoy emits forward-compat fields (`protocol_config:{}` + `metadata_context:{}`) that future proto versions may populate; rejecting these as "unknown" breaks cross-side interoperability.

**`HeaderValue.raw_value` is the canonical field per proto v1.17+ precedence rule.** Open Follow-up #2 (header-value emptiness) was both sides observing empty injected header values because the script set `Header.Value` (string) but reference Envoy v1.37.2 reads `RawValue` (bytes) exclusively. **Lesson:** for any new proto-consuming code involving `HeaderValue`, prefer `raw_value` per the proto-doc precedence rule ("if raw_value is set, it takes precedence over value"); the `value` field has been DEPRECATED since proto v1.17 (~2020). Reference Envoy's writer-side discipline is value-via-raw_value-exclusively; envoy-go's reader-side discipline now matches via Task 13 rework 2/3's `applyHeaderMutation` raw-value-preferentially reader.

**MVP-SUBSET disposition + in-place §Consequences AMENDMENT is the canonical ADR-0044-respecting pattern for partial-roster RATIFIED-PENDING-IMPL-TIME closures.** The §19.P4 9-counter MVP was hypothesized as the full reference roster; the empirical scrape RATIFIED it as a SUBSET. The disposition + in-place AMENDMENT (rather than a new ADR amending the roster) is the lighter-touch closure pattern — it documents the additional 8 counters as a future-activation surface without consuming a new ADR number. **Lesson:** when a RATIFIED-PENDING-IMPL-TIME pin's IMPL scrape reveals the hypothesis is a SUBSET (not a superset or a mismatch), the in-place §Consequences AMENDMENT pattern is preferable to a new ADR. The new-ADR escape-valve discipline should be reserved for ORTHOGONAL surfaces that surface at IMPL time (per the phase-18.2 ADR-0166 precedent).

**The codec-options axis vs envelope-content axis is a useful taxonomy for JSON-codec closures.** The §19.P8 RATIFIED-on-codec-options-axis disposition lets the closure narrative be precise: the codec-options (UseProtoNames + EmitUnpopulated + UseEnumNumbers) are byte-equivalent to reference; the envelope-content (whitespace + empty messages + value-vs-raw_value) is structurally-equivalent via `proto.Equal` round-trip, with three specific divergences DOCUMENTED-IN-PLACE for 19.2. **Lesson:** JSON-codec wire-shape claims should distinguish the codec-options axis (settable options at marshal time) from the envelope-content axis (the actual byte stream including whitespace + empty-message emission + field-choice semantics).

**D12 hypothesis HOLDING across 15 tasks is significant.** Phase 18.2 fired ADR-0044 twice (once at PLAN time per D12; once at IMPL-fixup time); phase 19.1 fired ADR-0044 ZERO times. The contrast suggests: when SPEC-time in-session SCRAPE closures remove the most-likely escape-valve surfaces (§19.P11 + §19.P12 in phase 19.1) AND the IMPL-time discoveries can be resolved via root-cause fixes + in-place §Consequences AMENDMENTS, no new ADR is needed. **Lesson:** the in-place §Consequences AMENDMENT pattern is a load-bearing companion to the SPEC-time SCRAPE closure discipline — both reduce the ADR-0044 escape-valve firing rate.
